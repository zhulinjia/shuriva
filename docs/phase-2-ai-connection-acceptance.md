# 第二阶段第一项：AI 配置与连接测试验收

本次交付完善模型设置、独立连接测试和模型错误反馈。真实模型与 SQLite 业务数据的完整联调仍属于本阶段后续工作，不能用测试替身的成功代替真实模型验收。

## 本次行为

- 已保存的服务地址和模型会回填到表单；密钥不会回显。
- 左侧列出 DeepSeek、OpenAI、Claude 和自定义服务，右侧编辑所选连接与模型列表；每家独立保存地址和密钥，下挂多个模型，互不覆盖。原有配置继续归为「自定义（OpenAI 兼容）」。
- 每个模型包含显示名称、API 模型 ID、启用状态，可增删、单独测试和设为默认；模型 ID 传给对应 AI SDK，不使用显示名称调用模型。
- 「测试连接」使用当前表单发起一次短 JSON 请求，最多等待 15 秒，不发送数据库结构、业务记录或工作台，也不保存表单。
- 「保存配置」只保存所选提供商，不代表连接已经通过测试，也不会切换当前使用的提供商。实例首次保存配置时自动启用该提供商。
- 「设为当前使用」明确切换默认提供商；创建页或右侧 AI 面板可为本次生成另选已启用的模型。切换编辑项不改变默认配置，有未保存修改时需先保存。
- 同一提供商、同一服务地址可以留空复用该提供商已保存的密钥，无论它是否正在使用；首次配置或更换服务地址时需要填写密钥。
- 缺少输入时显示字段提示；模型密钥被拒绝、权限不足、模型或接口不存在、限流、超时、响应无效等问题分别反馈。
- 连接测试不使用右上角或其他全局弹出通知。等待、成功和失败都显示在刚点击的按钮正下方；单个模型的结果与该行按钮对齐，底部测试的结果在底部按钮下方。结果持续保留，并禁止执行期间重复提交。
- 保存后刷新，密钥栏应显示「密钥已保存」与遮蔽占位，实际输入值仍为空。填写新值会显示「新密钥待保存」；更改服务地址时提示新地址需要密钥，不能误将原地址密钥当作当前地址已配置。
- 模型请求失败不自动重试；测试失败保留表单，生成失败保留需求、当前预览和已保存工作台。

## 多模型管理与选择验收

以下操作在「自定义（OpenAI 兼容）」下进行，使用本地替身完成，不需要真实服务商密钥：

1. 保留原 `test-model`，点击「添加模型」，显示名称填「备用本地模型」、API 模型 ID 填 `test-alt-model`。在该行点击「测试」，应单独测试此模型，显示通过；保存后刷新，两个模型仍在，密钥不回显。
2. 将备用模型设为默认并保存。创建工作台时「生成模型」默认项应显示备用模型，但仍能临时选择原模型；生成成功后默认配置不能被这次选择改写。
3. 在右侧 AI 修改面板切换生成模型并发起修改，预览和保存流程应正常；由创建页选择的模型会延续到新草稿的修改面板。
4. 停用备用模型并保存，它应从后续模型选项中移除。停用当前默认模型时，表单会选择另一个已启用模型作为默认；全部停用时，保存应显示启用提示。
5. 添加重复模型 ID 并保存，应提示对应行，不能覆盖已保存配置；移除该行后可正常保存。移除最后一个模型时应显示空状态，保存会要求至少添加一个模型。
6. 删除备用模型并保存，确认刷新后消失。恢复原 `test-model` 为默认，以继续其他本地验收。

选择器只展示已保存、已启用的模型。创建或修改中临时选择不会改变全局默认，也不会改变工作台的数据源绑定。若所选模型已被另一设备停用或删除，服务端在调用模型前拒绝，不会静默改用其他模型。

本地隔离环境可以保存测试用假密钥检查配置持久化，但不要用假密钥向官方服务测试或生成。完成界面验收后，把「自定义（OpenAI 兼容）」重新设为当前使用，以继续本地工作台验收。

即使服务地址相同，也不能借用另一提供商的密钥。Claude 使用原生 Messages 接口与 JSON Schema 输出；设置代理地址时，需要代理支持对应提供商的协议。自定义服务仍使用原有 OpenAI 兼容适配。

旧单提供商配置和版本 2 的多提供商配置都可读取，原模型、密钥和默认提供商保留，补充的预置模型默认停用；首次保存或切换时升级为加密的版本 3，多模型结构无需人工修改数据库。已有自定义模型不会因预置清单变化而被删除。

模型可用性以账号权限和实际连接结果为准。官方参考：[DeepSeek 模型与接口](https://api-docs.deepseek.com/quick_start/pricing/)、[OpenAI GPT-5.4 mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini)、[Claude 模型列表](https://platform.claude.com/docs/en/models/overview)。

## 真实模型验收

在独立的正式服务数据目录中启动应用，在「AI 设置」选择提供商并填写模型和密钥。默认使用官方服务地址，也可填写相同协议的代理地址。先测试再按需保存；不用把密钥发到聊天中。连接测试会调用该模型服务，费用由服务方计费规则决定。

测试通过仅表示这次请求成功、模型返回约定的 JSON，不代表所有工作台需求都能生成。后续还需用独立业务测试库验证生成、查询、保存、修改和异常恢复。

自动化检查使用本地模型替身，覆盖连接失败、超时、错误响应、密钥隔离以及失败后的数据保持；真实模型联调结果单独记录。
