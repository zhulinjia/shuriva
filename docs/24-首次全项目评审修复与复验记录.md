### 会话撤销的时点

认证继续使用 Better Auth。通过其公开 Kysely 适配器与 Kysely 事务，将凭据读取、密码校验、会话创建、改密与撤销放到同一事务连接；先锁定单管理员的用户行，与终端重设的用户行锁形成同一隔离边界。HTTP 入口的所有 POST 均使用该边界，产品路由继续独立限制开放端点；当前直接调用的用户名/邮箱登录与改密 API 也使用该边界。失败的 HTTP Response 与抛错都回滚。真实库测试观察到两个独立认证实例的行锁冲突，并用测试触发器让撤销失败，验证旧密码仍然有效、新密码没有部分提交。SDK 原始异常不允许绕过脱敏日志输出。

模型结构预览、生成和写入草案票据现在都要求服务端提供当前会话引用，并与结构任务及票据的发起会话一致；不同会话必须重新获取结构和确认披露。不能以同一账号的其他存活会话替代实际发送方的授权。已发布到 Connector 的读取不因后续会话失效改记为执行拒绝；停止重新派发并保留原签名结果，已派发却到期无结果时记为 `outcome_unknown`。

未派发的只读任务、尚未开始发送的模型请求必须重新核验发起会话；检查失败或数据库不可用均不能继续。会话引用仅为平台内存元数据，查询结果与审计保留规则不变。

会话核验的两秒单调截止包括获取连接、准备及执行语句。迟到取得的连接只释放，不再执行会话 SQL；已取得而停滞的连接销毁，不返回连接池。未完成的物理核验上限为 32，超时但尚未取得连接的等待仍占用名额直到归还，避免无限排队；不同请求不共享授权结果。拒绝审计的目标由明确的路由命名空间参数提供，再校验 UUID，仅表示尝试访问的目标，不证明对象存在或授予权限，不从原始 URL 猜测业务动作。

已经派发的任务或已经送达的模型请求可能已读取或披露信息，不能通过撤销追回这些信息；取消与丢弃迟到模型回复不等于证明数据库从未读取或模型从未收到。最终发送前直接重核，500 毫秒的受限会话监视仅用于及时取消等待，不作为强授权依据；会话查询有两秒超时，失败关闭。受控写入仍沿用其单独的会话锁及许可协议，正式开关继续拒绝。

### 复用方案与依赖

采用 [Better Auth hooks](https://better-auth.com/docs/concepts/hooks)，避免另造改密端点；使用 [mysql2 TLS 配置](https://sidorares.github.io/node-mysql2/docs/documentation/ssl)并验证实际认证降级拒绝。依赖补丁对应 [mysql2 凭据漏洞](https://github.com/advisories/GHSA-3f6p-5ww8-9rcr) 与 [multer 公告](https://github.com/expressjs/multer/security/advisories/GHSA-q7qp-rjg7-q26m)。

复用 Node test、Go testing、现有 Vite 模块加载器；为真实 React Hook 行为验证加入 React Testing Library 16.3.3 与 jsdom 30.1.3（MIT，仅开发依赖），依据 [renderHook 文档](https://testing-library.com/docs/react-testing-library/api/#renderhook) 与 [jsdom](https://github.com/jsdom/jsdom)。jsdom 的运行环境要求由项目 Node 24.19 基线满足；不把组件字符串匹配当作未保存保护的行为验证。

显式声明已在 Better Auth 依赖链使用的 Kysely 0.29.7 及 `@better-auth/kysely-adapter` 1.7.14（MIT），使用其公开事务和适配器接口，不引用内部模块。固定两处最小依赖补丁并纳入 lockfile：mysql2 在原始 socket 的 TLS 握手中传入真实 host，保证 IP SAN 按目标 IP 检验；官方 Kysely 适配器识别已有事务，避免 MySQL 插入后重新选择结果时误开嵌套事务。合成 TLS 测试使用公开测试密钥与自签证书，仅监听临时回环端口；证明 IP SAN 接受、只有 localhost SAN 的证书在认证前拒绝。证书、密钥均无真实服务用途；升级依赖时必须保留或用已验证的上游修复替换补丁。依据 [Node TLS](https://nodejs.org/api/tls.html#tlsconnectoptions-callback) 与 [Kysely 事务](https://kysely-org.github.io/kysely-apidoc/classes/TransactionBuilder.html#execute)。
