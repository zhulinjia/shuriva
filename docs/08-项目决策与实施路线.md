阶段划分、每阶段交付内容、测试及用户审核关口以 [分阶段开发与审核计划](09-分阶段开发与审核计划.md) 为准。计划覆盖既定产品范围，不以阶段划分删减功能；未经用户明确验收及必需检查通过，不将阶段标为已验收。若用户明确要求开始下一阶段，按其要求推进并如实记录前一阶段状态。

阶段 0 的计划和阶段 1 已由用户确认；阶段 2 待用户明确验收，阶段 3 按用户要求进行中。各阶段记录及其未决问题以分阶段开发计划为准。

## 4. 完成判定

- 每个功能有目标角色、权限、正常和失败流程、交付内容及可重复的验收标准。
- 每个关键模块明确职责、公开接口、允许依赖和所有权；自动检查覆盖已有的工程规则。
- 每项数据库或安全结论都注明 MySQL 版本、环境、测试结果和已知限制。
- AI 评审记录发现与处理情况；功能测试、隔离数据库集成测试及人工判断不能被评审结论替代。
- 标记为“已确认”“待验证”“已实现”或“已通过”时，必须有对应依据；未验证的初稿不得视为可上线。
