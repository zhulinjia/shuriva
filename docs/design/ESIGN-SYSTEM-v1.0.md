# 1. 设计目标

Shuriva 是 AI 业务工作台生成器。

设计目标：

让用户连接数据库后，快速生成并长期使用一个可信、清晰、可操作的业务工作台。

视觉方向：

**借鉴 Gemini 的蓝紫色视觉语言，结合专业 SaaS 的数据界面设计。**

关键词：

- Intelligent：智能
- Calm：平静
- Precise：精准
- Professional：专业
- Modern：现代
- Trustworthy：可信赖

核心原则：

1. 数据可读性优先于视觉装饰。
2. 专业性优先于炫酷效果。
3. AI 场景可以具有品牌辨识度。
4. 数据区域保持中性、清爽。
5. 渐变只用于品牌和 AI 相关区域。
6. 保留原有产品信息架构和交互流程。
7. 统一设计 Token，避免各页面独立发挥。

# 4. 语义色

状态颜色保持独立，不与品牌紫混淆。

| 类型    | 前景    | 背景    |
| ------- | ------- | ------- |
| Success | #18794E | #E8F8EF |
| Warning | #895B0D | #FFF6DD |
| Danger  | #B42336 | #FDECEF |
| Info    | #356AA8 | #EAF2FF |
| Neutral | #626A80 | #F3F4F8 |

使用规则：

- 成功：连接成功、保存成功。
- 警告：配置变更、未保存、需要确认。
- 危险：连接失败、删除、异常。
- 信息：提示、生产环境说明。
- 中性：普通状态、未激活。

状态不能只依靠颜色区分，必须同时提供文字或图标。

# 5. 渐变策略

渐变程度：Subtle。

允许使用：

### 品牌渐变

```css
linear-gradient(
  135deg,
  #6259D9 0%,
  #8276E8 55%,
  #A99AF5 100%
);
```

### AI 区域浅色渐变

```css
linear-gradient(
  180deg,
  rgba(98, 89, 217, 0.07) 0%,
  rgba(169, 154, 245, 0.035) 100%
);
```

使用范围：

- 品牌 Logo。
- AI 创建入口。
- AI 编辑器局部区域。
- AI 建议卡片。
- 少量品牌强调元素。

禁止：

- 整页大面积渐变。
- 数据表格渐变。
- 普通卡片大面积渐变。
- 输入框渐变。
- 大面积发光。
- 霓虹效果。
- 玻璃拟态。

核心原则：

AI 区域可以体现 AI 产品的视觉特色，但数据区域必须保持专业、清晰。

# 8. AI 专属视觉

AI 是 Shuriva 的重要能力，需要具备一定的品牌识别度。

## 8.1 首页创建入口

可以使用：

- 蓝紫色 AI 图标。
- 淡紫色背景。
- 轻微渐变。
- 品牌色聚焦边框。

但不能让输入区域过度装饰。

## 8.2 AI 编辑器

左侧 AI 面板：

- 背景：#FCFBFF
- AI 图标：蓝紫色
- 输入框：白色
- Focus：品牌紫
- 建议提示：#F1EEFF

右侧预览：

- 保持白色和中性背景。
- 表格与业务组件不使用大面积紫色。
- 清晰区分草稿和正式工作台。

核心原则：

AI 面板体现智能属性，工作台预览体现专业业务工具属性。

# 10. 字体与排版

候选方案：

A. 系统字体栈。

B. Inter + 中文系统字体回退。

C. Geist Variable。

| ------- | ---: | ---------- |

| h1      | 24px | 页面标题   |

# 14. Community / Cloud 设计边界

Community：

- 单用户。
- 单工作区。
- 自部署。
- 后端直接连接数据库。
- 支持多个数据库连接。
- 默认只读。
- 不显示团队权限入口。

Cloud：

- 多组织。
- 多成员。
- 多工作区。
- 字段权限。
- 行级权限。
- 工作台分享。
- 审计和团队管理。

Cloud 数据库连接方案仍然待定。

不得在视觉设计中预设必须使用独立 Connector 或浏览器直连。

# 15. React / Tailwind 落地规范

技术栈：

- React 19
- React Compiler
- TypeScript
- Vite 8
- Tailwind CSS 4
- shadcn/ui
- Base UI

要求：

1. 所有品牌色统一从 CSS Token 获取。
2. Tailwind 使用语义化颜色映射。
3. shadcn 默认灰阶和紫色变量必须与 Shuriva Token 统一。
4. 组件内禁止散落 raw hex。
5. 主题色不允许由单个页面自行定义。
6. 同类组件必须使用相同的设计 Token。
7. 不引入第二套完整 UI 组件库。

# 17. 最终设计结论

Shuriva Design System v1.0 采用：

**Gemini-inspired subtle purple-blue + Professional SaaS Data Workspace。**

核心视觉特点：

- 蓝紫色品牌体系。
- 淡蓝与薰衣草辅助色。
- 冷灰白色页面背景。
- 高可读性数据表格。
- 克制的局部渐变。
- AI 区域有辨识度。
- 数据区域保持专业中性。

本次设计升级不推翻 UI v0.2。

目标是将已有设计统一成一套专业、可复用、可维护的 Shuriva 品牌设计系统。
