# Shuriva UI v0.2 设计审查报告

> 审查对象：`preview/` 下 7 个 UI v0.2 原型页面
>
> 审查日期：2026-11-09
>
> 审查性质：只读分析与文档整理，未修改任何 HTML、React、CSS 或组件。
>
> 基线文档：[`DESIGN-BASELINE.md`](./DESIGN-BASELINE.md)
>
> 设计系统：[`DESIGN-SYSTEM.md`](./DESIGN-SYSTEM.md)

---

## 1. 审查结论摘要

UI v0.2 的核心方向成立，不需要推翻重做。当前问题集中在四类：

1. **关键流程的状态表达不可信**：刷新没有忙碌状态，连接测试成功后修改字段会静默禁用下一步。
2. **移动端信息被静默裁掉**：工作台第三个指标在最需要异常排查的手机上直接消失。
3. **设计 Token 没有收敛**：280 个唯一颜色、259 个一次性颜色、8–28px 十余级字号、3–13px 圆角。
4. **可访问性基础不完整**：大量 8–11px 文字、低对比度灰色、控件无可访问名称、表格语义被破坏、弹窗焦点不返回。

**问题数量：P0 4 项，P1 16 项，P2 12 项。**

建议顺序：先修 P0，再统一 Token / 字体 / 对比度，再处理组件可访问性与状态覆盖，最后做 P2 视觉细节。不要从"换皮"开始。

## 3. P0：影响功能理解、操作正确性或数据安全

### P0-01 品牌身份不一致：Stackoryn 与 Shuriva 混用

| 字段 | 内容 |
| --- | --- |
| 页面 | 全部 7 页；侧栏、页面标题、设置、CSV 文件名、localStorage |
| 现状 | 浏览器标题、侧栏品牌、可访问名称、演示账号、文案中的后端名称均为 **Stackoryn**；存储键为 `stackoryn-design-v02`；导出文件名为 `stackoryn-orders-mock.csv`。项目与产品文档使用 **Shuriva**。 |
| 问题 | 用户无法确认当前原型属于哪个产品；对外演示、交付、截图和文档会产生品牌混淆；后续代码、存储键和导出命名也会继续分裂。 |
| 建议 | 先由产品确认最终品牌。确认后统一：页面 title、侧栏品牌、`aria-label`、演示账号、文案、CSV 前缀、localStorage 键。存储键变更需提供旧键迁移或明确"重置演示数据"，不能静默丢失。确认前不要批量替换。 |
| 布局影响 | 无（文本与品牌资源）。 |
| 优先级 | **P0** |

### P0-02 移动端静默隐藏第三个指标

| 字段 | 内容 |
| --- | --- |
| 页面 | 工作台、编辑器预览 |
| 现状 | `@media (max-width:700px)` 中 `.metrics-strip>div:last-child{display:none}`；工作台指标变为两列，第三项"待核查订单"完全消失。编辑器预览在 980px 以下就隐藏第三项。 |
| 问题 | "待核查订单"是异常排查工作台的核心指标。移动端没有任何提示或替代入口，用户会误以为工作台只有两个指标，直接影响业务判断。 |
| 建议 | 移动端改为 1×3 纵向堆叠，或 2+1 网格；至少保留全部三项。若空间不足，使用更紧凑的指标行并提供"查看全部指标"，不能 `display:none` 静默删除。编辑器预览同步修正。 |
| 布局影响 | 中（仅移动端指标区；不改桌面结构）。 |
| 优先级 | **P0** |

### P0-03 添加数据源：测试结果被静默重置，下一步无解释禁用

| 字段 | 内容 |
| --- | --- |
| 页面 | 数据源 → 添加 / 编辑数据源向导（第 2 步） |
| 现状 | 连接测试成功后，任意 `ds-*` 字段变化都会执行 `testResult = null`，包括环境、示例业务数据、SSL 等非连接字段。此时"下一步"变成 disabled；界面没有说明原因。字段错误只在点击测试时以顶部 notice 出现，输入框没有 invalid 标记。 |
| 问题 | 用户测试成功后改一个配置，"下一步"突然不可用，容易卡在关键连接流程；顶部错误与具体字段没有关联，用户需要自己猜；对键盘和屏幕阅读器用户尤其困难。 |
| 建议 | 1）只有连接参数（host、port、database、username、password、engine、ssl）变化时才重置测试结果；2）"下一步"旁显示"请先重新测试连接"的原因；3）为必填 / 格式错误增加字段级错误、`aria-invalid`、`aria-describedby` 和错误摘要；4）测试成功后配置变化时显示"配置已变更，需要重新测试"，而不是静默清空。 |
| 布局影响 | 低–中（表单内错误文本和状态提示；不改变三步结构）。 |
| 优先级 | **P0** |

### P0-04 刷新没有真实忙碌状态，重复点击会叠加计时器

| 字段 | 内容 |
| --- | --- |
| 页面 | 工作台 |
| 现状 | 点击"刷新"设置 `A.ui.refreshing = true`，但渲染器和 CSS 都不读取该状态；按钮不禁用；每次点击都新建一个 550ms 的 `setTimeout`；完成 toast 可能来自旧点击；数据没有变化；模块没有 `aria-busy`。 |
| 问题 | 用户无法判断是否正在刷新；连续点击会叠加多个计时器，toast 互相覆盖；旧请求的"已完成"提示可能出现在新筛选条件下，让用户误以为当前数据已更新；屏幕阅读器没有状态可读。 |
| 建议 | 1）刷新按钮进入 busy / disabled 状态并显示 spinner；2）给工作台模块加 `aria-busy`；3）single-flight：新刷新取消或忽略旧计时器；4）完成结果按当前绑定来源状态生成；5）toast 明确"模拟刷新"，并区分成功 / 部分失败 / 失败；6）保留旧数据时显示"更新中"而不是假装完成。 |
| 布局影响 | 低（按钮内 spinner 与状态文案）。 |
| 优先级 | **P0** |

## 4. P1：明显的 UX / 视觉一致性问题

### P1-01 字号系统性偏小

| 字段 | 内容 |
| --- | --- |
| 页面 | 全部页面，尤其表格、权限、编辑器、移动端 |
| 现状 | 根字号 13px；8px 出现 24 次、9px 54 次、10px 85 次、11px 51 次。工作台表格 11px，表格辅助 9px，图表标签 8px；移动端权限表、规则代码、模块页脚、底部说明大量 8–9px。 |
| 问题 | 中文在 8–10px 下辨识度很差；高密度被错误地等同于"缩小字体"；低视力用户、普通笔记本屏幕和移动端阅读成本高。 |
| 建议 | 功能性文字不低于 12px，表格正文 13px，元信息 11px，8–10px 只允许用于纯装饰或非必要标记。通过行高、留白和列宽维持密度，而不是继续缩字。 |
| 布局影响 | 中（行高、表宽、卡片高度需要一起复核）。 |
| 优先级 | P1 |

### P1-02 文字、边框与图表对比度不足

| 字段 | 内容 |
| --- | --- |
| 页面 | 全部页面 |
| 现状 | 关键对比度：次要文字 `#7C8D9C` 在 `#F8FAFB` 上 3.26:1；表头 `#889EAC` 在 `#F9FBFC` 上 2.69:1；表格辅助文字 `#9BAAB6` 2.38:1；指标说明 `#97A7B3` 2.47:1；占位符 `#A1B0BD` 2.22:1；徽标文字 3.82–4.11:1；图表主柱 2.33:1、浅柱 1.60:1；输入 / 卡片边框约 1.22:1。 |
| 问题 | 违反 WCAG AA 对正文 4.5:1、非文字图形 3:1 的要求；弱视、低质量屏幕、强光环境下可读性差；边框太浅导致输入区域边界不清。 |
| 建议 | 使用 DESIGN-SYSTEM 中的语义色：`--text-muted: #61727F`、`--text-secondary: #556976`、表头 `#5F7280`、占位符 `#647684`；控制边框 `#80929F`；图表主色 `#0F766E` / `#448073`；徽标前景改为 5:1 级别。装饰性卡片边框可继续保持低对比，但输入框、复选框、焦点边界必须达到 3:1。 |
| 布局影响 | 无（颜色调整）。 |
| 优先级 | P1 |

### P1-03 搜索、筛选和下拉缺少可访问名称

| 字段 | 内容 |
| --- | --- |
| 页面 | 工作台目录、工作台表格、数据源、权限、角色预览、编辑器绑定 |
| 现状 | 多数搜索框只有 placeholder；表格筛选下拉没有 label / `aria-label`；工作台客户联动、角色预览、绑定选择、权限字段选择都缺少明确名称。 |
| 问题 | 屏幕阅读器只读出"编辑框 / 组合框"和当前值，无法知道用途；语音控制无法按名称定位；placeholder 在输入后消失，视觉用户也会失去上下文。 |
| 建议 | 为每个控件提供可见标签或视觉隐藏的 `<label>`；至少使用稳定的 `aria-label`。placeholder 只作为示例。筛选组使用 `fieldset + legend` 或分组标签。 |
| 布局影响 | 低（视觉隐藏标签不改变布局；可见标签会增加少量高度）。 |
| 优先级 | P1 |

### P1-04 选中 / 当前 / 展开状态缺少 ARIA

| 字段 | 内容 |
| --- | --- |
| 页面 | 全局导航、编辑器标签、权限标签、数据源分段筛选、步骤条、移动导航 |
| 现状 | 选中态只用 class `active` / `selected` / `current`；没有 `aria-current`、`aria-selected`、`aria-pressed`、`aria-expanded`、`role="tablist"`；移动导航按钮没有 `aria-expanded` / `aria-controls`。 |
| 问题 | 屏幕阅读器无法判断当前页面、当前标签、当前筛选和导航开关状态；键盘用户也缺少可预期状态。 |
| 建议 | 导航使用 `aria-current="page"`；标签页使用 `tablist / tab / tabpanel` 和方向键；分段筛选使用 `aria-pressed`；步骤条使用 `aria-current="step"`；移动导航按钮提供 `aria-expanded` 与受控区域。 |
| 布局影响 | 无。 |
| 优先级 | P1 |

### P1-05 表格行 `role="button"` 破坏表格语义

| 字段 | 内容 |
| --- | --- |
| 页面 | 工作台订单表、编辑器预览订单表 |
| 现状 | 每个 `<tr>` 被加上 `tabindex="0" role="button"`，只监听 Enter，不支持 Space；最后一列是装饰性 chevron，不是可聚焦按钮；表头与单元格的表格关系被角色覆盖。 |
| 问题 | 屏幕阅读器不再按表格导航；用户无法使用标准表格快捷键；Tab 顺序被每行打断；键盘用户无法用 Space 激活；行内没有明确的"查看"操作。 |
| 建议 | 保留原生 `<tr>` / `<td>` 语义；在最后一列放真实"查看订单"按钮或链接；如果保留整行点击，作为鼠标增强，不覆盖 role，并同时支持 Enter / Space。不要嵌套交互控件。 |
| 布局影响 | 低（最后一列增加操作按钮）。 |
| 优先级 | P1 |

### P1-06 弹窗焦点不返回，长表单可被误关闭

| 字段 | 内容 |
| --- | --- |
| 页面 | 数据源详情 / 向导、订单详情、绑定、重命名、确认、数据说明 |
| 现状 | `openModal` 只记录 `document.activeElement?.id`；多数触发按钮没有 `id`，关闭后焦点落到 `BODY`。没有显式初始焦点；点击背景会关闭；数据源向导关闭即清空表单，没有未保存确认。 |
| 问题 | 键盘 / 屏幕阅读器用户关闭弹窗后失去位置；长表单误点背景会丢失输入；焦点顺序不可预测。 |
| 建议 | 用 ref 记录触发元素并在所有关闭路径恢复；打开时聚焦标题或第一个可操作项；原生 dialog 负责焦点约束；数据源向导等长表单禁止背景关闭，关闭时确认；Escape 与关闭按钮行为一致。 |
| 布局影响 | 无。 |
| 优先级 | P1 |

### P1-07 移动端触控目标小于 44×44px

| 字段 | 内容 |
| --- | --- |
| 页面 | 全部移动端页面 |
| 现状 | 普通按钮 34px、compact 29px、icon-button 30px、编辑器发送 28px；移动端大量按钮仍为 26–34px；表格行高约 41px。 |
| 问题 | 触控误操作概率高，尤其数据源操作、目录行操作、编辑器发送和分页。 |
| 建议 | 移动端按钮、输入、图标按钮、分页、行操作至少 44×44px；紧凑样式仅用于桌面；相邻目标间距 ≥8px。 |
| 布局影响 | 中（仅移动端；会增加工具栏和行高）。 |
| 优先级 | P1 |

### P1-08 表单错误缺少字段级反馈

| 字段 | 内容 |
| --- | --- |
| 页面 | 添加数据源、重命名、策略保存、编辑器保存 |
| 现状 | 数据源测试失败只在顶部 notice 显示；字段没有 `aria-invalid`；编辑器保存失败只用 toast；重命名空值也只用 toast。 |
| 问题 | 用户不知道具体哪个字段错；屏幕阅读器无法把错误与字段关联；错误在滚动后可能不可见。 |
| 建议 | 字段下方显示错误文本，使用 `aria-invalid` + `aria-describedby`；顶部提供错误摘要并链接到字段；提交后聚焦第一个错误；保留已输入值。 |
| 布局影响 | 低（错误行会增加高度）。 |
| 优先级 | P1 |

### P1-09 禁用操作只把原因放在 `title`

| 字段 | 内容 |
| --- | --- |
| 页面 | 权限保存 / 预览、表格导出、数据源下一步 |
| 现状 | 保存策略、预览成员视角、导出 CSV 使用 `disabled title="..."`；下一步直接 disabled 没有原因。`title` 对键盘、触控和屏幕阅读器都不可靠。 |
| 问题 | 用户不知道为什么不能点，也不知道如何解除禁用；关键流程容易卡住。 |
| 建议 | 在按钮附近显示可见原因；或使用 `aria-disabled` 并保留可聚焦，点击时解释原因；不要只依赖 `title`。下一步禁用时显示"请先测试连接"。 |
| 布局影响 | 低。 |
| 优先级 | P1 |

### P1-10 设计 Token 漂移

| 字段 | 内容 |
| --- | --- |
| 页面 | 全部页面 |
| 现状 | 280 个唯一 hex，259 个只使用一次；根变量只有 13 个颜色；仅 85 处 `var()`；圆角 3–13px；间距 1–35px；页面最大宽度 1480 / 1400 / 1510；按钮高度 28–36px；同类灰色有多个近似值。 |
| 问题 | 同一语义在不同页面视觉不同；修复对比度或品牌色无法全局生效；后续 React 迁移会复制这套漂移；设计评审难以判断"哪个才是标准"。 |
| 建议 | 按 DESIGN-SYSTEM 建立语义 Token，停止在组件中写 raw hex；用 codemod / 手工映射收敛；保留例外必须命名并注明用途；建立视觉回归基线。 |
| 布局影响 | 单个改动低；全局收敛中。 |
| 优先级 | P1 |

### P1-11 标题层级与页头不一致

| 字段 | 内容 |
| --- | --- |
| 页面 | 首页、工作台、编辑器、权限、设置 |
| 现状 | 首页自定义 H1；其他页用 pageHead；编辑器工具栏标题是 `<span class="editor-title">`，没有页面 H1；部分页面 eyebrow 为英文，部分为空；分区标题 H2 / H3 层级不统一。 |

| 建议 | 每页一个 H1；编辑器标题改为 H1（可用视觉隐藏或 toolbar 样式）；分区用 H2，卡片用 H3；eyebrow 作为可选装饰，不参与标题层级；统一页头组件。 |
| 布局影响 | 低。 |
| 优先级 | P1 |

### P1-12 图表缺少可读数据与键盘访问

| 字段 | 内容 |

## 6. 跨页面系统性问题

1. **用字号换密度**：这是最普遍的问题。页面通过 8–10px 文字压缩信息，而不是通过列宽、行高和渐进披露。
2. **颜色没有语义层**：280 个 hex 中大量近似灰色，导致对比度修复无法全局生效。
3. **状态表达依赖视觉**：选中、离线、当前、展开、加载都缺少可读状态。
4. **交互反馈以 Toast 为主**：刷新、保存、导出、错误都容易变成"飘一下"，缺少模块内持久状态。
5. **表单错误不落地**：错误在顶部，不在字段旁，也不与字段关联。
6. **页面头不统一**：首页自定义、编辑器无 H1、英文 eyebrow 规则不一致。
7. **移动端做减法而不是重排**：隐藏指标、隐藏表头、隐藏环境信息，用户不知道少了什么。
8. **原型与 React 基座分裂**：青绿色 Inter 原型 vs 灰阶 Geist 脚手架，必须先对齐再开发。

## 7. 应该保留的正向设计

1. **克制的青绿色品牌**：没有渐变、发光、夸张装饰，符合数据工作台气质。
2. **工作台是主体**：日常使用不需要 AI 对话；编辑器是创建 / 修改工具。
3. **多数据源表达清晰**：每个模块显示来源页脚；单个来源离线不影响其他模块。
4. **Mock 边界诚实**：全局 Mock 徽标、AI"模拟响应"、权限"不是生产鉴权"、设置页边界说明。
5. **安全表达清楚**：只读、字段脱敏、记录范围、导出限制、CSV 注入防护、隐藏字段不出现在详情和导出。
6. **AI 编辑器交互成熟**：草稿 / 已保存状态、放弃确认、生成中停止、变更清单、`Ctrl/Cmd + Enter` 中文输入法友好。
7. **权限页结构完整**：角色、字段、记录范围、数据源、导出、AI 授权分层清楚。
8. **数据源向导完整**：三步、测试连接、模拟失败、访问范围、只读标识。
9. **基础可访问性已起步**：`focus-visible`、原生 dialog、`aria-live` toast、减少动效。
10. **响应式有明确断点**：1750 / 1250 / 980 / 700，移动端有专门布局，不是简单缩放。

## 8. 暂不修改清单

在进入页面优化前，以下内容应保持：

- 青绿色主色 `#0F766E` 与现有灰蓝中性色方向。
- 220px 侧栏、56px 顶栏、工作台主 / 右双栏、编辑器 320px + 预览双栏。
- 首页创建区、工作台目录、数据源列表、权限三标签、设置卡片的信息架构。
- shadcn/ui + Base UI + Tailwind 4 + React 19 + Vite 8 + TypeScript 技术栈。
- Community / Cloud 能力边界与"连接方案待定"的表述。
- 所有 Mock / 只读 / 非生产鉴权标识。
- AI 不生成任意 HTML / JS、不直接执行未验证 SQL 的产品约束。
- 工作台与编辑器共享同一渲染器的结构。
