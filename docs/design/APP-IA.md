# Shuriva 应用信息架构（当前实现）

> 状态：已实施。
>
> 更新日期：2026-11-10。
>
> 本文记录当前 React 应用的路由与页面职责。`DESIGN-BASELINE.md` 是 UI v0.2 原型的历史基线，不再代表应用入口结构。

---

## 1. 决策

应用采用 **工作台优先（workspace-first）** 的入口结构：

- 工作台是产品主体，打开应用先看到已保存的工作台。
- 创建是独立、明确的动作，只有一个入口。
- 不在应用内保留第二个营销 / 落地页；产品介绍由官网或公开文档承担。
- 数据源连接管理独立成页。

此前同时存在首页（`/`，带创建表单和最近工作台摘要）、创建页（`/create`）和工作台目录（`/workspaces`），创建入口重复、工作台视图重复。现在取消独立首页。

## 2. 路由与职责

| 路由 | 页面 | 职责 |
| --- | --- | --- |
| `/` | 重定向 | 重定向到 `/workspaces`（`replace`） |
| `/workspaces` | 我的工作台 | 搜索、按数据源筛选、打开、重命名、复制、删除工作台 |
| `/workspaces/:workspaceId` | 业务工作台 | 日常查询、筛选、详情、多源状态，右侧常驻 AI 修改 |
| `/create` | 创建工作台 | 描述需求、选择数据源、生成进度、草稿预览与 AI 对话、保存 |
| `/editor/:workspaceId` | AI 编辑器 | 修改已保存工作台的既有流程 |
| `/datasources` | 数据源 | 连接管理、状态、使用情况、添加数据源 |
| `/permissions` | 成员与数据权限 | 团队版设计预览 |
| `/settings` | 设置与演示 | 产品模式、故障模拟、重置演示 |

## 3. 导航

主导航：

- 我的工作台（`/workspaces`）
- 数据源（`/datasources`）
- 成员与数据权限（仅 Team 预览显示）

侧栏顶部保留唯一的主操作「创建工作台」→ `/create`。品牌标识链接到 `/workspaces`。

面包屑不再保留「首页」层：

- 我的工作台：`我的工作台`
- 创建工作台：`我的工作台 > 创建工作台`
- 工作台：`我的工作台 > 工作台标题`
- 数据源 / 设置：仅当前页名称

## 4. 原首页内容的去向

| 原首页内容 | 现在位置 |
| --- | --- |
| 需求输入框、数据源选择 | `/create` 创建入口 |
| 3 个模板按钮 | `/create` 的「从一个业务场景开始」（点击填入需求） |
| 「继续你的工作」最近工作台 | `/workspaces` 目录本身；侧栏「最近使用」 |
| 「数据已就位」数据源概览 | `/datasources` |

`src/app/pages/home-page.tsx` 已移除，备份位于 `.backup/home-page.tsx`。

## 5. 行为约束

- `/` 只做重定向，不再承载创建表单。
- 首次使用时，`/workspaces` 的空状态提供「创建工作台」引导。
- 创建入口、生成进度、草稿预览和 AI 对话仍为本地 Mock，不连接真实数据库。
- 权限、查询限制、字段权限和行级权限必须由可信服务端执行，不因入口调整而改变。

## 6. 工作台与 AI 面板

- 工作台页面和创建预览采用左侧画布、右侧常驻 AI 面板；中间分隔线可调整宽度，窄屏上下分区。侧栏宽度是当前浏览器的显示偏好，不写入工作台配置。
- AI 修改与数据源绑定修改先进入草稿。保存后更新工作台；放弃时恢复已保存版本。侧栏显示本身不产生草稿，也不会因为保存或放弃而关闭。
- 创建预览和已保存工作台使用相同画布及布局模型。预览使用无数据占位，不能把模拟数据或占位值当作真实查询结果。
- 工作台组件按可用宽度自动排列和换行，不提供组件拖动、交换或手动调整尺寸。旧版本保存的布局字段保留在数据中，但当前界面不再读取或修改该字段。
- 真实查询、授权及安全校验仍属于可信服务端。
- 当前保存和版本冲突检查只覆盖本地 Mock 浏览器存储，并不代表跨设备同步或服务端并发控制已经实现。
