# 第四阶段实施与审核记录

**状态：已由用户审核通过。** 第四阶段仅在下述已验证范围内验收；MySQL 8.0 和任意视图的元数据副作用仍未验证，不能称为生产就绪。第二、第三阶段的审核状态不因本阶段验收改变。项目尚未上线，不设计假设旧版兼容；不得擅自修改用户现有数据库或凭据。

## 本阶段目标

实现并独立验证 MySQL 只读 SQL 安全引擎：在 Connector 上使用明确的 MySQL 解析器、逐节点允许列表、授权的库表字段及本地只读凭据，接收并验证绑定身份和作用域的任务；支持参数化执行、超时与取消、结果资源限制及明确的截断状态。平台还需验证工作区、数据源绑定和当前授权。SQL 子集以实际解析、名称绑定和隔离数据库测试证明的结果为准；不能证明安全的语法、对象、函数和视图拒绝执行。写入仍关闭。

## 开始前的验证与边界

- 当前开发测试实例报告 MySQL 26.7.0，MySQL 8.0 尚未验证；测试仅可使用单独实例、单独测试库和受限测试账号，不使用或修改用户现有实例。
- 解析器应有适合项目的许可和维护记录，与 Connector 当前 Go 工具链兼容；需确认解析器对服务端版本、SQL 模式、注释和单条语句的处理，未知情况失败关闭。
- 对象和字段授权必须与 SQL 实际解析语义一致，不能信任平台声称已授权；本地策略、数据库权限和最终执行检查共同约束查询。视图及不明作用的函数在证明安全前拒绝。
- 参数、SQL 及结果可能敏感，不得作为调试信息、错误或长期记录泄漏；结束、撤销、断线与超时不能留下失控任务。

## 进度与已验证结果

- Vitess `v0.22.4`（Apache 2.0）在当前 Go 1.26 Windows 386 环境因其 Swiss map 构建条件无法编译，未用于 Connector。TiDB MySQL Parser（Apache 2.0，固定 `v0.0.0-20241218021942-d13e52ed6e22`）可在同机 `GOARCH=amd64` 编译运行；当前 32 位构建对查询校验返回不可用，仍可运行原有 Connector 功能。候选验证程序保存在 `research/`。
- 新增独立的 `queryguard`：按当前 SQL 模式解析恰好一条语句，在明确的表/字段范围内编译为全新参数化 SQL。当前已验证的语法仅支持单表显式字段、简单参数条件和排序；别名、通配字段、函数、视图、连接、子查询、联合查询、字面值和其他未验证形式均拒绝。拦截注释是额外防线，最终不执行用户输入原文。
- 新增 Connector 本机工作空间、基础表和字段的只读范围配置：配置前核对实际结构，默认无权限；撤销工作空间时清除对应范围。配置本身不开放执行。
- 64 位测试覆盖允许及危险 SQL、多语句、注释、越权字段与未知模式；使用独立 MySQL 26.7.0 的临时数据库和受限账号验证参数化查询，测试只清理自身创建的数据。32 位测试验证明确拒绝；两种架构 Connector 回归测试通过。
- 本地只读执行器读取本机授权并复核数据库账号，只允许已验证的 MySQL 26.7.0、InnoDB 基础表、表名大小写设置和 Go 驱动实际 SQL 模式；在只读事务中读取并锁定结构，拒绝视图及不在范围内的字段。结果限制行数、总字节与单字段大小，并标记截断；高精度小数按文本、二进制按 base64 返回，会话时区设为 UTC。取消或超时后通过驱动关闭不确定的连接。
- 新增签名查询、取消及结果的 Go / TypeScript 契约和共享向量；Connector 执行协调器验证签名及范围、预先记录任务防止重放，并能接受绑定当前任务的签名取消。隔离测试覆盖被阻塞查询的取消、视图表达式未执行、元数据锁与并发 DDL、结果截断及高精度/二进制值。
- 平台任务、心跳派发、结果校验和查询接口可通过 `ENABLE_STAGE4_READS=1` 显式启用，默认关闭，且要求已启用第三阶段。平台只在内存中短暂保留任务和结果，并在解绑、归档或撤销后取消任务及清除结果；Connector 在开始前复核本地策略，平台回传前复核绑定。完整隔离链路测试通过了只读查询、字段越权拒绝、排队及执行中取消、执行中解绑、解绑后重绑及结果清除、未登录与跨来源请求拒绝。隔离测试自动创建并删除临时平台库、数据源库和受限账号，没有操作用户本机数据库。
- 修复任务下发后、执行器启动前的取消竞态，以及结果回传确认与下一任务派发重叠时可能丢任务的竞态。Connector 生命周期测试及隔离数据库跨进程测试验证了执行中撤销身份后连接器停止、结果不再发布。测试发现，取消后 Connector 能关闭连接并拒绝返回结果，但 MySQL 上等待表锁的线程可能在锁释放后才消失；不能承诺取消会立即停止数据库端的所有工作。
- 审核中发现 Node MySQL 驱动和 Go 驱动的会话 SQL 模式不同；实际执行器只接受使用 Go 驱动验证过的模式，其他组合失败关闭。两种客户端的读数不能互相替代为兼容性证明。
- 完成查询界面：选择工作区绑定的数据源，输入 SQL、有类型参数与行数限制，查看结果和截断提示，或取消查询。切换来源/离开页面清除本地结果；断线后只恢复任务状态，不自动重新提交 SQL。独立端口的模拟数据浏览器复核覆盖输入、结果、截断和取消；随后使用专门创建的隔离数据库与受限账号，验证了真实浏览器、平台、Connector 到 MySQL 的只读查询链路，并验证未授权字段被拒绝。
- 连接器结果发送中断时，在任务期限内仅重签并重发已有内存结果，不重新执行 SQL；平台对合法重发幂等确认。取消、撤销和进程退出会停止投递。平台或连接器进程重启可能丢失未确认的内存任务或结果；此时明确提示结果未知，由用户核实后决定是否重新提交，系统不会自动重新执行。
- 增加同一工作区的授权与结果发布顺序控制，以及同一连接器的结果读取与撤销顺序控制；并发测试覆盖解绑、查询创建、结果访问和连接器撤销。结果发送前验证签名，避免未认证请求占用工作区锁。
- 数据库端先限制字段大小，再由客户端限制总结果：测试了 8 MiB 大字段、字符集扩张、NULL、二进制、BIT、日期、UTC、JSON 和高精度数值。最终结果上限为 1 MiB；单行在驱动读取前的理论数据上界约为 256 × 32 KiB，另有协议和内存复制开销。该约束不防御恶意伪造 MySQL 协议的服务器，也不等于数据库服务端内存上限。

## 审核方式与未决限制

本阶段实现、故障测试和安全复核已完成受限范围的开发验证，并已由用户审核通过；默认启动仍不开放查询。要在**已准备好第三阶段表结构的隔离开发环境**演示，可同时设置 `ENABLE_STAGE3_DATASOURCES=1`、`ENABLE_STAGE4_READS=1`，为绑定数据源配置本机表/字段授权并运行 64 位 Connector。不要为演示擅自修改现有数据库。其他 MySQL 版本、SQL 模式和架构均失败关闭，MySQL 8.0 尚待独立测试。网络隔离或数据库长时间持锁时，取消不保证服务器线程立刻退出。视图元数据副作用未经穷尽证明，当前仅应在受信任的数据源上使用；不能据此宣称安全支持恶意数据库或生产环境。

本次临时审核演示运行在 [独立回环地址](http://127.0.0.2:13102/)，使用单独创建的合成平台库、数据源库、账号和 Connector；示例 `SELECT id, name, city, balance FROM customers` 返回合成客户数据。演示进程与数据仅用于本机审核，不依赖或修改用户原有数据库；进程重启后该临时入口可能不可用。

## 审核问题修复与复核

- 数据源绑定或连接器状态暂时查询失败时保留查询面板及当前任务；确认解绑、撤销或工作空间失效后才清除。短暂网络失败不应触发取消。
- 查询提交使用客户端生成的请求编号；提交响应丢失时使用相同编号和内容重试。心跳响应丢失时平台重复派发同一任务，Connector 在执行和结果回传期间防止重复执行；取消早于提交到达时也阻止迟到提交。跨进程重启或无法确认结果时明确提示，不自动重复查询。
- 查询令牌与服务实例及当前工作空间、数据源授权绑定；解绑或重新绑定使旧令牌失效。签名结果绑定原任务 nonce，拒绝迟到的旧结果，避免影响新任务。短暂数据库读取故障不会被当作授权撤销。
- 活跃任务与未读取结果分别限额，完成任务释放活跃名额，未读取结果不会为了腾容量被静默丢弃。结果在清除、离开或开始下一次查询时释放；容量不足会提示用户等待或清理结果。Connector 的防重放记录采用有界分片，满时拒绝新任务而不删除仍有效的记录；重置中途失败会保持身份不可用并允许重试清理。
- 浮点数和空间字段采用正确的返回格式；整数参数支持有符号 64 位范围及 MySQL 无符号 64 位最大值。空值条件支持 `IS NULL`、`IS NOT NULL` 和 `字段 <=> ?`；普通比较不能绑定空值，避免得到容易误解的结果。
- 额外检查了授权变化、重启、旧结果、取消与提交乱序，以及容量耗尽和请求过大的错误路径；服务端明确拒绝时界面应立即给出原因，普通临时错误仍可安全重试。

本轮验证：前端 30 项测试通过；平台任务、授权及取消容量专项 21 项通过；跨语言真实 HTTP 丢包和隔离数据库查询测试通过；Connector 凭据库防重放与重置故障测试，以及独立 MySQL 上的数据类型和查询测试通过。实际浏览器在隔离演示中验证普通查询返回 3 行，`IS NULL` 查询按预期返回 0 行。项目格式、静态检查、类型检查及前端构建通过。所有数据库测试使用专用隔离实例及合成数据，不修改用户现有数据库。本机 Go 未启用 CGO，未执行 race 检测。

安全研究发现：MySQL 在 `PREPARE` 完成后释放准备阶段的元数据锁，不能依赖先检查表类型再准备并执行来阻止并发 DDL 将表替换为视图。隔离 MySQL 26.7.0 中，事务内 `SHOW COLUMNS` 对基础表和视图阻止并发 DDL，测试视图中的锁函数没有执行；不能据此将结果扩展到其他服务版本或任意视图。对基础表的 `SHOW CREATE TABLE` 实验没有阻止并发 DDL，也不能替代该锁。显式 `LOCK TABLES` 会影响其他会话写入，未作为执行方案。执行器设置了会话级元数据锁等待和 SELECT 执行时间限制，仍不能保证所有数据库端操作立刻停止。需要继续针对对象身份和视图副作用作故障及安全评审，未验证时保持拒绝。参考 [MySQL 元数据锁文档](https://dev.mysql.com/doc/refman/26.7/en/metadata-locking.html) 和 [MySQL 子查询限制](https://dev.mysql.com/doc/refman/8.0/en/subquery-restrictions.html)。
