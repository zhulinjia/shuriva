# 架构边界与技术验证计划

**状态：** 设计初稿；已有前后端和 Connector 初始化骨架、基础检查，但尚无自动化流水线或已验证的数据库迁移。  
**范围：** 完整产品，包括 Community、Cloud、MCP、Connector 和受控写入；按依赖实现、验证和交付，不以阶段划分删减产品能力。\
**基线：** 当前本地测试使用 MySQL 26.7.0，平台数据库和首批用户数据源均以 MySQL 为目标；MySQL 8.0 兼容性、部署条件、支持范围及工具链待验证。Community 采用 Apache 2.0 开源，Cloud 为独立私有仓库。实现规则以 `AGENTS.md` 为准，执行安全以 `03-SQL安全执行引擎设计.md` 为准。

## 1. 职责、数据所有权与依赖

下表描述职责与代码依赖，**不要求每一行独立部署或单独建包**；实现时按变化边界和真实用例决定拆分。调用表示依赖方向，不代表所有模块互相直接调用。

| 区域 | 负责什么 | 可依赖的边界 | 禁止或限制 |
| --- | --- | --- | --- |
| 领域模型与规则 | 工作区、数据源、查询、变更等业务概念及不变量 | 基础语言类型、同领域纯规则 | 不依赖 Web 框架、ORM、驱动、Cloud 或具体部署 |
| 应用用例 | 编排认证后的请求、授权检查、查询/变更流程和事务边界 | 领域规则、应用端口及公开契约 | 不直接创建 Prisma Client、数据库连接、模型供应商客户端 |
| Query / Action / Policy | 计划、策略与确认语义；按能力组合应用用例 | 领域类型、公开端口、经过版本化的策略契约 | 不以 UI、提示词或上游 `allowed` 为最终执行授权；不跨语言直接引用实现 |
| Schema / Semantic | 结构快照、业务语义、元数据来源和解释 | 数据源、结构读取端口、公开领域接口 | Schema 注释和数据是非可信输入；不绕过数据源授权 |
| AI Runtime / Provider | 上下文组织、结构化计划、模型适配及结果解释 | 应用用例、模型端口、授权范围内的数据 | 不持有数据库执行权限；不把模型输出视为可信命令 |
| Web | 展示、输入和交互状态 | 公开 API、UI 模型与共享 UI | 前端状态不作为授权依据；不直连用户数据库 |
| Community / Cloud API、Worker | 传输、身份上下文、作业和依赖装配 | 对应应用用例、明确公开契约 | 控制器不承载核心业务规则；Community 不依赖 Cloud |
| 持久化、模型、认证和 Broker 适配器 | 把接口连接到 Prisma、外部服务、身份或 Connector | 所实现端口及对应基础设施客户端 | 内部实现和数据表仅由所属模块使用；避免 ORM 类型穿透到领域 |
| Connector | 本地认证、数据源密钥、策略执行、MySQL 连接、任务与审计 | 公开的跨语言协议、Go 本地实现和数据库驱动 | 不导入 TypeScript 包；不能因云端声称允许就绕过本地策略 |
| MCP 入口及外部客户端 | 将授权的应用能力映射成工具；管理用户批准的外部服务 | 应用公开接口、认证和权限检查 | 外部工具返回内容不可信；工具发现不代表可调用或可访问任意网络/进程 |

Public Core 不依赖 Community 应用或 Cloud 私有实现；Cloud 经版本化公开接口复用 Public Core，不能依赖 Community Prisma Client。共享领域数据经公开用例、事件或明确的只读接口获取，不直接读写其他模块的表；跨模块报表需要定义数据归属和一致性策略。应用层编排跨模块操作，数据库事务不能被假定跨服务或跨用户数据库自动生效。

## 2. 跨进程、跨语言与版本兼容

Connector 协议归属 Public，采用**语言无关**的消息契约和共享测试向量。TypeScript 和 Go 分别使用生成物或各自适配实现；不能将架构图中 Go 对 Contracts / Policy 的箭头解释为 Go 直接导入 TypeScript 包。序列化格式、传输方案和生成工具由验证决定，确定后固定版本和兼容策略。

协议设计必须明确：

1. **连接与身份：** 注册配对、可信根、服务端身份验证、凭证保存、轮换、吊销及失联恢复；明确 Community 和 Cloud 的信任差异。
2. **任务绑定：** 任务 ID、执行 ID、工作区、数据源、操作者或授权主体、操作类型、策略版本、消息版本、签发和到期时间、防重放标识。Connector 核实本地允许的数据源和策略，并处理权限撤销。
3. **用户确认：** 指定由谁签发、Connector 如何独立验证，以及确认凭证如何绑定规范化计划、值、目标、期限与策略；防重放且单次使用。平台消息签名只能证明签发方，不能单独证明用户确认。若威胁模型要求抵抗已被攻陷的平台伪造确认，必须设计独立信任来源或本地确认机制；否则明确该限制，不能宣称能够防止平台伪造确认。
4. **生命周期：** 接收、排队、执行、取消、完成、失败和结果未知的状态转移；超时、重连、重复投递和撤销的处理。查询、写入的重试策略分开定义。
5. **结果与错误：** 稳定错误码、可重试性、结果大小与截断标记，安全处理诊断信息；大整数、十进制、时间及二进制字段规定无损表示。
6. **演进：** 明确当前消息格式、能力及未知字段和未知操作的处理。项目尚未上线，不为假设的旧版本保留兼容窗口；平台和 Connector 同步演进。不能理解的安全要求必须拒绝，不得静默降级；使用跨语言契约测试阻止协议漂移。

契约至少提供有效样例、无效样例、边界值、重放和旧版本样例，供 TypeScript 与 Go 双向编码解码和行为测试。版本发布、兼容窗口、策略签名算法及密钥生命周期目前均待确定。

## 3. 代码质量与自动化门禁

初始化已固定 Node.js、pnpm、TypeScript 和 Prisma 基础版本，并配置构建、类型检查及基础测试；MySQL 具体小版本与完整工具链仍待验证。下表是目标检查清单，其中持续集成、依赖边界、完整安全及发布检查尚未建设，不能视为已通过。

| 检查 | 要验证的结果 | 建议触发时机 |
| --- | --- | --- |
| 格式、静态检查与类型检查 | TypeScript / Go 规则一致，错误与不安全类型可见 | 每次代码变更及持续集成 |
| 依赖边界 | Shared Core 不依赖应用、Cloud、Prisma 和具体驱动；模块只访问公开入口；检测循环依赖 | 每次代码变更及持续集成 |
| 构建与依赖锁定 | 从干净环境按固定版本安装并构建相关应用、共享包及 Connector | 每次代码变更；发布前完整构建 |
| 行为与契约测试 | 关键领域不变量、权限决策、错误分支及 Go / TypeScript 协议向量 | 相关模块变更及持续集成 |
| 数据库与故障集成 | 使用隔离 MySQL 验证迁移、约束、访问权限、事务、超时、断线及恢复 | 相关变更；发布前对支持版本矩阵执行 |
| 端到端与安全测试 | 用户流程、权限绕过、提示注入、结果限制及失败反馈 | 相关能力验收与发布前 |
| 供应链与发布 | 依赖许可、密钥泄漏、漏洞、SBOM 及构建产物完整性 | 合并或发布时按风险运行 |

规则以实际可运行的配置、脚本和持续集成结果为准；选择具体工具前验证跨 Windows 与目标部署环境的可用性。逐步建立分层测试：纯规则用单元测试，进程与协议用契约测试，MySQL 用隔离实例做集成测试，关键用户路径做端到端测试。安全与故障测试必须验证外部可观察结果，不只断言内部实现。

对数据库模型，先验证初稿，再生成受版本控制的迁移；覆盖空库、已有版本升级、失败后的前向修复、备份恢复、字符集/排序规则、时区及唯一约束。禁止对用户生产库试验。多版本升级路径只有在存在真实历史迁移后才能验证。

## 4. 技术验证清单

每项验证需保存：假设、候选方案及版本、可复现环境、测试输入、结果、风险、选择原因和失败时替代路径；通过前功能保持关闭或拒绝。以下均为待办。

| 验证主题 | 关键测试或问题 | 通过标准与后续处置 |
| --- | --- | --- |
| MySQL 与平台模型 | 真实服务版本、驱动和 Prisma 兼容；隔离数据库迁移、索引、字符集、时区、备份恢复 | 目标版本矩阵通过；发现不兼容则修改模型和迁移，不直接应用初稿 |
| MySQL 解析与对象授权 | 对比解析器与实际服务端对 `sql_mode`、可执行注释、引号、多语句、CTE、视图、别名、`SELECT *` 和函数的处理；验证字段与对象解析 | 支持的子集一致且权限准确；未知语法或无法证明对象身份时拒绝 |
| 只读与资源保护 | 检验数据库实际生效权限、只读事务边界、结果大小、取消、超时和连接池复用 | 非授权写入和危险查询被拒绝；超时或取消后事务及连接状态可确认或安全丢弃 |
| 认证、配对与策略 | 配对、轮换、撤销、过期、防重放、工作区解绑、任务来源伪造、策略回滚与云端失陷假设 | Connector 在所有入口独立拒绝无效任务；本地限制及信任根无法被普通远程任务静默覆盖 |
| 确认与受控写入 | 确认人与计划/参数绑定、过期与重放；InnoDB 主键集合与版本复核、并发新增/修改/删除、触发器和权限变更 | 不一致时不提交并要求重新确认；未经授权或无法验证的写入拒绝，完成安全评审前不开放 |
| 断线与故障恢复 | 重复确认、重复派发、连接中断、提交前后崩溃、超时与取消 | 若目标库同事务去重不可用，提交结果不明时标记未知并禁止自动重试；可复现并验证人工核对流程 |
| MCP 与提示注入 | 认证、工具权限、外部地址及命令、SSRF、数据脱敏、恶意工具输出和数据库注释 | 工具只能访问授权能力；不可信内容不能提升权限，外部连接和进程规则待定义并验证 |
| AI 查询评估 | 以脱敏测试数据覆盖正确 SQL、字段歧义、无权数据、结构变化、提示注入、结果截断和模型不可用；记录各 Provider 的数据发送范围、超时与成本 | 保留可复现样例与预期行为；更换模型、提示词或工具协议时回归，模型答案不得覆盖程序安全校验 |
| 发布与部署 | Community 独立运行、Cloud 引用公开核心、平台和 Connector 的安装配置与升级 | 干净环境可复现；版本兼容和回滚或前向修复有记录 |

查询用户数据库与平台数据库权限应分离，用户数据源读写账号应分离；保护机制不因使用同一 MySQL 服务而省略。写入预览保存的参数与目标摘要可能是敏感信息，须定义访问权限、加密、有效期、备份与清理策略；哈希不能替代执行所需的值。
