# 第九阶段：MCP Server 与 Client 设计及验收计划

2026-11-01。用户指示进入下一阶段，按 [阶段计划](09-分阶段开发与审核计划.md) 开始阶段 9。本文件是 G1 设计交付，尚未实现 MCP、安装 SDK、执行外部工具或修改数据库；不把选型与设计当作功能验证。阶段 8 的 [G4 技术验收](25-第八阶段G4补齐与验收记录.md) 不等于授权本阶段开放写入或为原数据库安装对象。

## 1. 交付范围与当前事实

本阶段完整覆盖两个方向：

- **平台作为 MCP Server：** 外部客户端通过本地 stdio 或远程 Streamable HTTP 使用经批准的工作区能力；可查看授权、有效期、最近调用及撤销状态。
- **平台作为 MCP Client：** 管理外部 HTTP/stdio 服务，发现并逐项批准工具，展示调用内容、进度、结果与错误，管理 OAuth/API 凭据引用。

Server 与 Client 分别验收，不能做完其中一个就宣布阶段完成。Cloud、Desktop 的专属实现仍按后续阶段推进；公开核心和 Community 可独立运行，不依赖 Cloud 私有授权服务。

已核对当前代码：

| 当前事实 | 对本阶段的约束 |
| --- | --- |
| `packages` 目前仅有 `ui`，没有 MCP 实现 | 下文模块路径均为拟建边界，不是已存在能力。 |
| `queries/public.ts` 的公开用例仍围绕 `ReadService`，`ReadJobs` 登记真实 `sessionId` | 不能把 MCP token、grantId 或固定 admin 标识塞进浏览器会话字段。 |
| `ScopeCoordinator` 已统一工作区、数据源和 Connector 身份检查 | MCP 复用当前授权与绑定检查，不复制一套较宽松的查询执行器。 |
| 普通 API 的写入配置仍拒绝启用，普通 Connector 没有挂载写入 Handler | MCP 不能利用新传输绕过门禁；关闭时不提供可执行写工具。 |
| 查询、语义、审计有部分公开边界；`mutations/public.ts` 尚不存在 | G2 根据真实调用需要补公开端口，禁止 MCP 包直接导入应用内部 service/store。 |
| Better Auth 当前为 1.7.14，并有事务适配补丁 | OAuth 适配须回归现有登录、退出、改密、会话撤销与日志脱敏，不能用 SDK 示例覆盖现有认证。 |

## 3. 模块与执行主机

| 拟建模块 | 职责与依赖 |
| --- | --- |
| `packages/mcp-contracts` | 框架无关的主体、范围、工具描述快照、调用状态与端口契约；不依赖 Express、数据库驱动、Community 或 Cloud。 |
| `packages/mcp-server` | SDK Server、HTTP/stdio 协议映射，依赖公开能力端口；不直接查询应用表或连接用户数据库。 |
| `packages/mcp-client` | SDK Client、发现/调用、协议错误转换及取消；凭据、网络策略、进程拥有者由端口注入。 |
| `apps/community-api/src/mcp` | Community 授权、配置、调用元数据存储适配器、管理 API 和应用用例装配；只管理本领域表。 |
| `apps/community-web/src/mcp` | 授权列表、连接配置、工具审批、调用及进度界面；不承载安全规则。 |
| 本机 MCP 执行宿主 | 在 Connector 所在的受信主机运行 Node SDK Client/stdio 适配，使用该主机的安全凭据库和已批准的进程/网络策略。与 Go Connector 之间的拥有关系及私有 IPC 在 G2 验证。 |

当前单机开发可以验证同机部署；不能据此假定平台与 Connector 永远同机。分离部署必须有可核验的执行宿主身份和受保护的任务/凭据交接，否则该连接保持不可用，不把密钥迁入平台数据库作为回退。Cloud 只实现相同公开端口，不被共享包反向引用。

G2 的公开端口以实际变化点为限：授权解析、工作区能力调用、调用结果披露、外部执行、凭据引用、审计。接口名称在编译验证后固定，不为每个类增加接口。框架控制器负责协议与输入边界，权限交集及状态迁移属于应用用例，存储适配器负责自身事务；DTO 不直接作为领域授权对象。

现有 `modelFetch` 绑定聊天接口路径，不能直接拿来发送 MCP 流量。可提取经回归验证的地址分类/连接固定原语，MCP 与 OAuth 的所有请求仍需各自执行完整端点校验。

## 4. Server：身份、授权与工具

### 4.1 远程 HTTP

HTTP 使用 Streamable HTTP 和 MCP OAuth 资源发现规范，Community 采用自己的 Better Auth 授权服务。浏览器登录 Cookie 只用于管理员登录和审批；`/mcp` 数据面只接受针对该资源的 MCP 凭据，不能把 Cookie 当外部客户端授权。

G1 建议先验证用户委托的授权码 + PKCE S256，管理员登记或审核客户端；不启用匿名动态注册、client_credentials、跳过同意或默认 offline_access。客户端名称只是展示资料，不证明程序发布者身份。必须显示 clientId、回调目标、工作区、数据源、字段范围、允许操作、结果接收方和有效期。

凭据设计优先验证不透明 access token、哈希保存和逐次校验，避免为此把 JWT 私钥默认存进数据库。插件 opaque 模式、resource 绑定和哈希存储必须先用实际版本确认；不满足就停止该候选并重新选型，不能自行削弱检查。建议 token 5 分钟，授权最长 8 小时且不超过批准它的真实管理员会话有效期；具体值集中配置，刷新不得延长已撤销授权或越过会话期限。

每次工具列出、调用、结果读取及重连都检查：令牌有效性及确切 resource、客户端、授权世代、原批准会话仍有效、当前工作区/数据源绑定和本机策略。失效或核验超时失败关闭。退出、密码恢复、撤销会话或客户端授权会使相关授权失效；不能只校验 JWT 签名后缓存到过期。协议会话/状态句柄只用于路由和恢复。

工具上下文显式传递不可变主体，不在共享 Server、连接或全局变量中保存可变的“当前管理员”。撤销要同时阻止继续使用与刷新原授权，不把删除一个 access token 当作撤销整个授权；插件的会话/consent/刷新家族映射必须在 G2 验证。

issuer、resource 和审批 URL 来自受信配置，不能从 Host/Forwarded 或工具参数猜出。配置非回环地址使用 HTTPS；校验 Host 和已出现的 Origin，拒绝未批准来源。CLI 没有 Origin 不代表已认证，仍必须有有效凭据。OAuth 新端点单独按协议处理 JSON/表单、PKCE 和客户端身份，不能因此放开整个 `/api/auth`、公开注册或现有 Cookie 管理 API 的来源检查。

以上为项目拟定策略；规范依据为 [MCP 授权](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization) 与 [官方 Server 授权指南](https://github.com/modelcontextprotocol/typescript-sdk/blob/main/docs/serving/authorization.md)。SDK 默认值及示例不是项目授权结论。

### 4.2 本地 stdio

stdio 适配器本身不创建管理员身份、不直连平台数据库。管理员先在界面批准本地客户端，再由受信本机助手将短期凭据写入安全库；客户端配置只保存非敏感授权引用。stdio 进程按引用读取自身凭据，通过公开能力端口访问平台，仍逐次核验范围和撤销。具体同机/分离交接在 G2 验证，不能把不受保护的 TCP 端口当私有 IPC。

**同 OS 用户不是独立应用隔离。** 用户级安全库、不同令牌、凭据命名空间、程序摘要和非敏感引用，均不能阻止同一用户的另一进程取得该用户可读取的凭据。引用不充当客户端身份证明；本机应用显示名也不是安全主体。

本地接入区分两种明确模式，未批准时均无权限：

- **同用户受信域：** 将该执行主机同一 OS 用户下的本地 MCP 客户端视为同一信任主体。管理员批准域级范围与有效期，界面明确同域程序可使用该范围；域内应用登记仅用于管理/追踪，不宣称程序身份认证或分别限制权限。撤销操作是整组撤销该域授权；不能声称只撤销 B 后，B 便无法利用仍有效的 A 域凭据。不得预设这个域拥有管理员全部权限。
- **独立隔离客户端：** 如需互不信任的本地客户端分别授予权限、单独撤销，必须先验证 OS 强制的独立身份/凭据隔离及绑定实际对端身份的受保护 broker。不能只检查父 PID、程序名称/哈希或调用方自报的 clientId。G2 未证明该能力前，此模式保持禁用；不能自动降级到同用户受信域。

部署与 UI 必须显示实际支持哪种模式。若管理员要求独立客户端隔离而执行宿主只有同用户权限，拒绝该配置，不能仅给两份凭据假称已隔离。HTTP bearer 同样只能证明持有有效授权，不证明本机程序发布者或防止同用户窃取其他客户端凭据。

标准输出只承载 MCP 协议。密钥不出现在命令参数、工具描述、配置示例或日志；本地启动不使用 HTTP OAuth 回调替代其本机凭据流程。凭据与授权主体必须绑定实际信任域或已核验隔离身份，禁止使用默认管理员令牌。

### 4.3 计划中的工具清单

工具参数不接受 ownerId、sessionId、token 或“已批准”标记来提升权限。客户端使用授权内的领域标识，服务端解析真实主体和绑定。

| 工具 | 作用 | 执行与披露边界 |
| --- | --- | --- |
| `workspace_list` | 列出已授予的工作区 | 只返回授权内的最少元数据。 |
| `datasource_list` | 列出已绑定且已授予的数据源 | 不含凭据、未授权来源或全局存在性信息。 |
| `schema_describe` | 查看选定表/字段结构与允许披露的说明 | schema/语义权限单独授予；敏感说明默认不发送。 |
| `query_prepare` | 提交受限只读计划供管理员核对 | 返回待审批状态和不含参数的审批链接，不自动执行。 |
| `operation_status` | 核对本授权自己的调用与已同意披露的结果 | 不接受任意 query/execution ID 越权查结果；超限必须明确标记。 |
| `operation_cancel` | 取消自己的待审批/执行请求 | 已发送请求只尝试取消，不承诺撤回已产生的事实。 |
| `change_propose` | 把结构化变更草稿交给管理员 | 不产生提交许可；写入口关闭时明确不可用。 |

不提供任意 SQL、DDL、数据库授权、原始密码或通用 shell 工具。SDK 的 sampling、动态工具注册、资源自动读取等能力不因库支持就默认开启。

### 4.4 Server 接收边界

限制覆盖 HTTP、stdio、未认证请求、初始化、工具发现及所有工具调用，不能只限制进入交接区的计划。以下为 G2 要验证的配置初值：

- 在 SDK 解码前按实际字节流计数，单个 JSON-RPC 消息最多 64 KiB，工具参数/计划另限 32 KiB；Content-Length 只作提前拒绝依据，chunked/分段输入也必须计数。默认拒绝压缩请求，防止解压绕过。stdio 未出现消息边界而持续输出，也要在超限时终止自身通道。
- 在任何 SDK 递归验证或对象遍历前限制结构深度 32、总节点 2048、数组/属性数量和字符串大小；若适配器先解析 JSON，只能在固定字节预算内解析并做有界非递归结构检查，再交 SDK。必须查找可复用的 SDK/解析器限额能力，不编写不完整的 JSON/JSON-RPC 解析器。
- 初始 Header 预算 8 KiB，从接受连接起到完整收到 Header 的绝对截止为 5 秒；Header 完成后，请求体另有 5 秒绝对接收截止，不能随零星字节重置。保持连接上的后续请求也逐次限制 Header/请求体接收时间；stdio 单条消息从首字节到完整边界同样限时。慢速不完整 Header、无边界 stdio 输入必须主动终止，不能等业务层超时。TLS/反向代理如承担这些接收边界，也必须验证其实际配置，不能只假定上游已限制。
- 认证/解码工作不无限排队；每授权最多 4 个、进程最多 32 个在途请求，并限制全局连接数。速率候选为已核验主体与授权家族各 60 次/分钟、突发 8 次，同用户本地模式另按整个信任域合并计算；进程合计 600 次/分钟、突发 32 次。未认证来源另限 10 次/分钟、突发 2 次，并服从全局预算。初始化、发现、无效调用与结果轮询均计入；刷新/新建传输不能重置主体或家族预算。超额拒绝，不堆入无界队列；未知来源不能靠伪造 clientId 分摊限额。具体限额在 G2 通过正向与压力测试后固定。
- 超限、非法编码、深层/超大消息和慢输入返回固定错误并释放本请求资源，不能记录原始请求体或把解析失败标成业务失败/成功。HTTP、stdio 的限额分别验证正向下界与负向故障，不能用 HTTP 框架的普通 JSON 配置推断 SDK 内部也有界。

如公开 SDK 挂载点无法建立这些边界，保持对应入口关闭并调整适配方案；不能先上线再依靠后续业务参数校验防护。

## 5. 保留现有审批与执行链路

### 5.1 只读查询

G1 默认逐次审批，不因授予“可准备查询”就自动执行或返回结果。流程为：

1. 外部客户端提交结构化计划，服务端先验证 MCP 授权、输入和作用域，返回 `approval_required`、调用编号及审批入口。
2. 管理员使用自己的真实浏览器会话查看已核验的授权主体、目的地、SQL/参数、行数上限及本次结果接收范围。同用户本地模式明确写“结果可由该主机同一 OS 用户信任域内的程序取得”，不能写成仅返回某个应用；应用名称若展示，只标注为未核验资料。HTTP 授权或已验证隔离模式展示相应真实授权主体，不能以显示名称代替它。
3. 显式批准后，调用现有查询用例；Connector 继续做 MySQL 解析、允许列表及最终授权。不能伪造 sessionId、借用另一管理员 Cookie 或另开数据库连接绕过 Connector。
4. 为这个调用登记授权世代、真实批准会话、目标绑定与披露约束，内容承诺包含实际接收主体及其模式，不能批准应用 A 后改为整个域。新增公开结果读取端口同时核验这些约束，MCP 调用方不能借内部读取接口任意查其他任务。同用户域的凭据不能提供域内应用间的结果隔离，审批页必须在同意前明示。
5. 排队、发送前、等待期间和披露前重新核验；撤销时停止新发送、尝试取消在途读取并禁止继续披露。没有结果就不能显示成功，也不自动重跑。

管理员编辑 SQL、参数或目标后必须重新生成内容承诺并核验审批，不能在同一批准下换内容。执行权限及返回字段均取 MCP 授权、真实管理员权限、当前绑定和本机策略的交集；管理员自身的更大权限不会自动扩展外部客户端授权。超出原授权时重新申请范围，或明确转成不向 MCP 披露结果的独立查询。

需要新增的授权收紧信息必须进入经签名的内部任务契约，并在 Connector 最终执行校验中生效；不能只缩减 tools/list 或 UI 展示。G2 确定所需字段时同步修改当前 Node/Go 调用方、签名覆盖和共同向量，不为尚未发布的项目保留旧协议分支。

待审批计划和参数仅进入有容量与时限的内存交接区，元数据可持久登记。建议单项 32 KiB、2 分钟；重启丢失时明确过期，不能凭摘要重新执行。业务请求使用显式 UUID 幂等标识，不能使用可重置的 JSON-RPC 消息序号；记录按授权主体、世代、工具版本和请求标识绑定内容摘要，拒绝同标识换内容。过期/重启后的同标识返回原终态或明确不可恢复，不重新建立执行。敏感参数不直接保存为可离线猜测的裸摘要，采用带密钥的承诺。

若后续需要长期自动执行只读查询，应另行明确授予范围、数据披露和领域主体类型并验证，不把当前真实会话约束直接删掉。本阶段交付仍可通过标准工具完成准备、审批、结果核对和取消全过程，不用挂起一个网络请求等待人类审批。

### 5.2 受控写入

`change_propose` 只交接草稿。它返回 `handed_off` 或待管理员处理，不能返回“已提交”。管理员打开后明确接收该草稿，再通过现有 MutationPanel 生成新的完整预览、核对全部前后镜像并确认。MCP 不提供替代管理员的 `confirm`/`execute` 工具。

交接仅包含有界、短期、一次性草稿，绑定授权、工作区、数据源与内容承诺；URL 只含不具独立授权能力的引用，不含 SQL、参数或密钥。草稿过期/平台重启后无法恢复时如实报告，不能自动生成或确认另一操作。

管理员接收并重新检查后创建的是其独立授权的操作，关联原调用用于审计；外部授权不因交接获得执行权限。原授权撤销后，外部客户端不能继续查看后续结果；管理员若仍要自行操作，界面明确提示已转为自己的新操作。取消 MCP 草稿不是撤销数据库 Commit。阶段 8 门禁、原编号、许可、未知冻结和只读恢复规则全部保留。

## 6. Client：外部服务与执行安全

### 6.1 HTTP 与 OAuth

- 默认只接受明确配置的 HTTPS 端点。目标私网/回环地址需要本机管理员按协议、主机、端口和执行宿主显式批准；不把所有 localhost、所有私网或当前平台控制面作为允许目标。
- MCP 请求、重连、重定向、OAuth 发现、授权服务器元数据、token、JWKS/CIMD 等关联请求均经过同一受信网络策略。检查所有解析地址，连接固定到已批准地址，防止检查后重新解析；混合非法地址、元数据服务、userinfo URL、跨目标转发凭据和未批准跳转拒绝。
- 复用 SDK OAuth Client 流程，验证 state、PKCE、issuer、resource、redirect 和回调的一次性绑定。发现一个不同 issuer 不自动授信，先展示并批准其目的地。回调不能凭 URL 参数 ownerId 归属账号。
- 现有 Cookie 的跨站回跳行为必须验证；回调完成不自动启用连接或执行工具，仍由原管理员在平台完成确认。密钥存入实际执行主机安全库，平台表只保存引用与非敏感状态。

### 6.2 本地 stdio

本地程序可能具备宿主用户权限。环境变量筛选、工作目录和 Job 对象均不是文件/网络权限沙箱；不能声称仅批准一个工具就约束了恶意程序的全部本机行为。

默认只允许管理员明确批准、已安装且来源可信的程序/安装包：固定绝对路径、入口/依赖完整性与启动参数；程序或依赖变化后重新审批。禁止模型自选命令、shell 拼接、`cmd /c`、PowerShell 脚本执行器及隐式 `npx`/下载后运行。未知程序保持拒绝；执行不可信代码需要另有已验证的 OS 身份/容器隔离，不通过 UI 勾选伪装安全。

启动前展示执行主机、程序、参数、工作目录和权限说明；参数及持久配置不得含密钥。子进程只获得该连接所需的最少环境值，不继承平台数据库连接、管理员会话或其他连接密钥。执行宿主应在启动前建立拥有关系，设置资源/时间上限并在退出时关闭自己的进程树；不能按进程名称批量终止其他服务。Windows 拥有与异常回收须在 G2/G4 实测后开放 stdio 运行。

### 6.3 工具审批、结果与未知状态

发现不等于授权。工具清单只展示，默认不调用；按 connectionId、工具快照版本和明确操作策略批准。readOnlyHint/destructiveHint、名称及工具描述都不是事实或授权。工具 schema、程序或目标变更使旧批准失效，重新发现不会静默扩权。

单次调用前展示目的地、已批准工具版本、实际参数及发送范围；外部工具可能产生副作用，参数批准不能推导为允许发送任何数据库数据。工具结果先进入隔离的结果视图，按不可信内容处理；不自动执行其中的指令、访问 URL/资源、加载远程图片或发送给 AI。进入模型上下文前沿用明确披露与同意流程。

状态至少区分 `pending_approval`、`running`、`succeeded`、`failed`、`cancel_requested`、`outcome_unknown`、`expired`。网络失败、超时、进程崩溃或协议取消不证明外部副作用未发生；不得自动重试。仅对已验证为无副作用的协议发现/连接握手进行有界重连；不根据工具名或 hint 自动轮询一个所谓 status 工具。

初始建议边界为每连接 1 个在途调用、每管理员最多 16 个在途/待审批外部调用、工具清单 100 个、描述 4 KiB、schema 64 KiB、单次结果 1 MiB，且服从更严格的本地策略。SDK 解码、schema 编译、引用和深度也必须限额，不自动获取远程 `$ref`；拒绝无法有界验证的输入，不悄悄裁剪 schema。具体配置上限通过 G2 压力与边界测试固定，不作为已测性能承诺。

连接/发现候选时限为 10 秒、单次外部调用 60 秒，管理员可在已批准策略上限内配置，不能静默续期。界面立即显示已知阶段和已耗时长；没有真实进度通知时写“等待外部服务响应”，不虚构百分比或模型思考过程。`succeeded` 只表示收到符合协议/结构的工具结果；界面使用“已收到结果”，不把第三方自报成功当作平台独立核验的业务事实。

规范风险依据见 [MCP 安全实践](https://modelcontextprotocol.io/docs/2026-07-28/tutorials/security/security_best_practices)。上述信任、审批和进程策略是本项目拟定约束，不能由第三方工具描述更改。

## 8. 持久化、凭据与审计

拟议领域记录为客户端登记、McpGrant、ExternalMcpConnection、ToolSnapshot/Approval、McpInvocation 和权限关联。授权主体区分 HTTP 客户端、同用户本地信任域和已核验的独立隔离客户端；后两者由执行宿主核验，不能从客户端名称或引用猜出。每个表由所属模块维护；OAuth 插件自己的表由认证模块管理。MySQL DDL、事务、索引、分页及保留时间在 G2 针对实际 SDK 模型确认后另交迁移稿，本轮不生成或执行迁移。

授权撤销、登记调用及必要审计元数据要有明确事务/幂等契约。审计持久化失败时不开始新调用，保留原调用事实；已发送后的审计故障不能把真实结果改写成未执行。无效或未授权的输入 ID 只能作为受限尝试元数据，未核验前不能填入带领域关系的有效 scope，避免污染审计补投。

不保存原始 OAuth/API token、明文 client secret、SQL 参数、外部工具完整输入/输出或本地环境值到平台表、普通配置及日志。不可逆 token 校验材料与凭据引用可以按用途保存；插件额外表必须做 canary 检查，不能把“库默认加密/哈希”当已验证。数据库密码仍仅由 Connector 所在环境持有；本阶段不得上送或复用它们。

诊断使用固定事件与错误码，记录 requestId/invocationId、已验证 scope、连接/工具版本、耗时、字节数与有限结果分类；不记录原始异常、Authorization、OAuth code/回调查询串、argv/env 或工具结果。审计事件在实际用例中声明，禁止通过 URL/工具名称猜测行为。
