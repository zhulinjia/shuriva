# 第九阶段绑定代次实施与隔离验证

状态：绑定身份、MCP 草稿来源及受控变更预览的实现与专项验证完成；独立 Agent 审查和 Codex 原生 Review 由主任务统一安排，当前尚未完成，不标为审查通过。本记录不替代第九阶段其他验收。

## 实际设计与取舍

使用独立迁移 `009-binding-identities.sql`，而不是修改已执行的阶段 3/8 SQL、其校验和或已有业务列。`source_binding_identity` 以工作区/数据源复合主键引用真实绑定，存储服务端生成的 UUID v4；解绑由外键级联删除该身份，每次重新绑定在同一事务生成新身份。同一 Connector、同一工作区和同一毫秒均不能复用原代次。唯一索引防止重复，插入异常使整个绑定事务回滚；不覆盖其他绑定。

`mutation_preview_binding` 保存预览对绑定代次的承诺，通过外键引用预览。它不代替 Connector 目标身份、目标 epoch、完整快照、策略代次、安装代次、会话、确认编号或阶段 8 的其他校验。预览、确认、首次执行领取和许可签发都在来源模块提供的真实数据库锁内核对当前 Connector 与代次，不能依赖进程锁或前端状态。

选择侧表是为了保持现有业务数据和已执行迁移定义不变，同时避免阶段 3 严格结构校验接受多种列形状。代价是装配必须明确识别此模块，预览多一次映射写入，来源读取多一次身份查询。未安装模块时不查询这些可选表，已有无关读取与恢复事实可以继续；新预览、确认、首次执行领取、许可签发一律拒绝。能力接口明确返回 `binding_identity_required`。运行时不自动回填缺失身份。

`ScopeCoordinator.withBoundIdentity` 专用于短时草稿安全交接，保持工作区进程锁、Connector 锁、平台数据库工作区/来源/绑定锁的次序；获取 InnoDB 行锁最多等待 5 秒，结束后恢复池连接原配置。MCP 提交捕获代次、管理员查看、领取与接收均在该段内核验；敏感发送沿用已有授权期限、断线和取消信号。模型调用和普通 Connector 查询继续使用原来的范围协调，不持有新增的数据库锁。

来源证明只由已核验的浏览器领取回执建立，绑定管理员会话、工作区、数据源、Connector、代次及原计划承诺。浏览器只能提交来源调用编号，不能选择或覆盖权威代次。预览前核验来源，异步 Connector 预览返回后再次核验，保存时在真实事务内复核。解绑重绑使旧证明失效。已接收草稿的管理员仍可在外部授权撤销后独立操作，但要通过当前本地会话、绑定、Connector 策略和确认要求。

外部调用持久状态继续保留 `handoff_unknown`；这既不表示执行成功，也不表示浏览器接收或人工审核。来源证明是最多 128 项的进程内承诺，重启、淘汰或提交结果未知后不重发、不恢复可用来源。生产入口默认不启用 MCP 草稿，受控写入执行仍关闭；真实执行仅由显式隔离测试装配开启。

## 显式迁移与恢复

入口为 Community API 的 `db:migrate:bindings`，必须显式提供迁移命令所需环境变量及目标数据库；先核验阶段 3/8 的既有完整结构。实际执行前须停止所有绑定写入实例；迁移命令不会停止其他应用或自动操作默认数据库。本次不对用户原库执行迁移或修改任何数据。

1. 获取目标数据库专用迁移锁。只释放自身持有的命名锁。
2. 检查已存在侧表的引擎、字符集/排序规则、全部列、默认值、生成表达式、索引顺序/唯一性/可见性/前缀、引用同库的完整外键及动作；拒绝未知触发器/CHECK。只建立缺失且定义已知的表，不覆盖不同结构。
3. 以最多 100 个真实绑定为批次，在事务内锁行并为缺失身份生成随机 UUID。已回填身份保持不变，不新建不存在的业务绑定，不改 `boundAt`、所有者或其他业务字段。
4. 验证 UUID 格式与唯一约束，记录独立版本/SQL 校验和，最后重新完整核验。MySQL 对 SQL 中未声明的外键 UPDATE 动作实际报告 `NO ACTION`，实现按本次隔离实例的真实元数据核验，没有推断为 `RESTRICT`。

DDL 隐式提交，整个迁移不能作为一个事务回滚。中断后重跑同一显式命令：根据实际结构恢复缺失表，从未回填绑定继续；回填事务内错误回滚当前批次；提交后报错则保留已提交身份。元数据记录后失去响应也只重新核验，不分配新代次。结构、格式、版本或校验和不同均停止，不能当作修复命令覆盖。

迁移前已存在的无代次预览保留原数据，不猜测它曾属于哪次绑定，不生成预览映射；迁移后不得确认这些预览。迁移不构成恢复这些预览的执行授权。
