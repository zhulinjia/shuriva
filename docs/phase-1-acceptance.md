# 第一阶段：登录和只读工作台验收

本阶段用于确认产品方向和基础链路，不是正式生产版本。验收环境使用独立的临时数据，SQLite 数据库是真实文件，AI 服务是本地固定回复的测试替身；它不能证明真实模型理解能力。

## 启动隔离验收环境

在项目目录执行：

```powershell
pnpm install --frozen-lockfile
pnpm build
pnpm exec tsx tests/browser-fixture.ts
```

保持终端运行，访问 <http://127.0.0.1:4318>，使用测试账号 `admin`，密码 `shuriva`。测试环境的数据与正式服务分开。停止服务后再次启动会创建新的临时数据。

## 建议验收步骤

1. **登录与数据源**：登录后打开「数据源」。预置的「验收测试库」应显示为 SQLite、只读。首次使用正式服务时，需要运行 `pnpm admin` 初始化账号，并自行连接数据源。
2. **创建和预览**：返回「我的工作台」，点击「创建工作台」。在原有的创建入口填写“查看记录”，点击「选择数据源」并选择「验收测试库」，然后点击「开始构建工作台」。生成后左侧应显示「记录工作台」，表格中出现 Alpha、Beta；点击「下一页」应看到 Gamma。右侧 AI 面板宽度可以调整。
3. **保存与恢复**：点击顶部「保存工作台」，返回列表，再次打开「记录工作台」。刷新浏览器后重新打开，已保存的工作台仍应存在。
4. **修改与放弃**：在右侧 AI 面板输入“修改标题”并生成修改，标题应变为「已修改的记录」。点击顶部「放弃修改」，标题应恢复为「记录工作台」。输入“增加图表”时，测试替身会返回明确标记「待接入」的图表占位。离开未保存草稿时应提示确认。
5. **日常操作与退出**：可按表头排序、选择字段搜索或翻页；缩窄窗口后页面不应出现整体横向溢出。点击「退出登录」后应返回登录页。

验收替身只针对以上输入返回固定结果。真实 AI 连接需在正式服务的「AI 设置」选择 DeepSeek、OpenAI、Claude 或自定义兼容服务，填写对应的地址、模型和密钥，再连接真实数据库进行单独验证。AI 服务会接收用户需求、所选数据源的表和字段结构以及当前工作台配置；已有查询的筛选值在发送前被遮蔽，不发送数据库记录样本。

如需另外测试添加 SQLite 数据源，可打开 <http://127.0.0.1:4318/test-info>，复制 `path` 字段，在「数据源」页面添加。该地址和测试账号只存在于隔离验收环境，不存在于正式服务。

## 已有范围与限制

- 所有真实数据查询在服务端执行；每个查询绑定一个数据源，数据源凭证加密保存在服务端，默认只读。
- AI 输出必须通过受控 Schema 验证；当前可真实显示的业务组件仅有表格、详情和单值展示；未支持的需求可以用标记为「待接入」的占位组件保留。单值展示读取查询第一行的字段，不代表自动聚合指标。
- 基础组件已从 shadcn/ui 引入并保留原有样式；引入不等于所有组件都已适配为 AI 可使用的业务组件。
- 原有目录中的重命名、复制和删除入口仍保留，但当前正式界面标记为“待接入”；左侧「设计演示 · 模拟功能」可查看现有模拟界面。
- PostgreSQL / MySQL 的连接代码尚未用真实数据库验证；字段和行级权限、写入授权与 CRUD、CSV/XLSX/JSON 导入导出、图表、受控样本、Docker 和生产部署尚未完成。
- 该阶段的 SQLite 查询采用只读连接与独立工作线程，但尚未完成大数据集性能、完整安全审计和生产环境验证。
- 保留的 `/workspaces`、`/datasources` 等旧路径是本地模拟设计演示，其数据不属于真实服务。
