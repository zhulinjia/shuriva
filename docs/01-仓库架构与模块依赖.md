# AI Database Workspace

## 仓库架构与模块依赖设计

**文档版本：** V0.1\
**状态：** 工程设计基线（待实现验证）\
**适用范围：** Community Edition / Cloud Edition\
**核心原则：** 一个共享核心、两种产品形态、两个代码仓库。

------------------------------------------------------------------------

## 产品范围与实施顺序

2026-11-02 用户明确取消桌面软件。当前交付范围为 Community Web、Connector、MCP、独立 Cloud 和发布运维，架构与目录按此范围规划。

产品按下文完整架构规划，平台数据库和首批用户数据源使用 MySQL。用户同意当前本地测试使用实测的 MySQL 26.7.0；原计划的 MySQL 8.0 和正式支持范围仍待验证。功能按依赖分阶段实现与验证，不以 MVP 缩减既定范围。写入、MCP 和 Cloud 均属于产品目标；未通过相应权限、安全及集成验证的能力不得开放。

## 1. 总体决策

用户已确认采用两个 Git 仓库：

  -------------------------------------------------------------------------------
  仓库                      可见性            许可证/性质       主要职责
  ------------------------- ----------------- ----------------- -----------------
  `ai-database-workspace`   Public            Apache 2.0        完整开源核心及
                                                                Community Edition

  `ai-database-cloud`       Private           商业私有代码      Cloud SaaS
                                                                专属能力
  -------------------------------------------------------------------------------

### 1.1 Public 仓库包含

-   Community Web / API / Worker
-   Shared Domain、Contracts、Application Services
-   AI Runtime、AI Provider 抽象
-   Database Engine、Query Engine、Action Engine
-   Policy Engine、Schema Engine、Semantic Engine
-   Dynamic UI Schema 与 Renderer
-   Go Local Connector
-   Remote MCP Server（Streamable HTTP）
-   Local MCP Server（stdio）
-   MCP Client
-   SDK、Docker 部署、文档和示例

### 1.2 Private 仓库包含

-   Cloud Web / API / Worker
-   SaaS 身份认证
-   Tenant、Organization、Membership、Invitation
-   团队 RBAC 与团队协作
-   Cloud AI / Model Proxy
-   Connector Broker 与集中管理
-   Cloud MCP OAuth / 授权
-   Usage、Billing、Subscription
-   企业运营后台、生产部署和监控

开源版必须能够在不注册 SaaS、不连接商业 Cloud
API、不使用商业授权服务器的情况下独立安装和运行。

## 5. 依赖规则

  依赖方向                                规则
  --------------------------------------- ----------------------
  Community App → Shared Core             允许
  Cloud App → Shared Core                 允许，通过版本化依赖
  Community → Cloud                       禁止
  Shared Core → Cloud                     禁止
  Shared Core → Community App             禁止
  Cloud → Community Prisma Client         禁止
  Connector → Public Protocol Contracts   允许

### 5.1 共享核心只能有一份

Cloud 应通过 Git Tag、Semantic Versioning
或发布到私有/公共包仓库的版本化包引用 Public Core。禁止把核心代码复制到
Private 仓库长期维护两份。

示例：

``` text
ai-database-workspace
  v0.1.0
  v0.2.0
  v0.3.0

ai-database-cloud
  depends on shared-core@0.3.0
```

### 5.2 两套持久化实现

Community Prisma Schema 和 Cloud Prisma Schema
必须独立。可以共享领域模型、DTO 和接口，但不能让 Cloud 直接依赖
Community Prisma Client。

## 6. Shared Core 的接口设计

共享核心依赖抽象端口，不依赖部署形态。

``` typescript
export interface DatabaseExecutionPort {
  executeQuery(request: QueryRequest): Promise<QueryResult>;
  executeAction(request: ActionRequest): Promise<ActionResult>;
}
```

Community Adapter 通过本地 Connector 执行；Cloud Adapter 通过 Cloud
Connector Broker 执行。

模型 Provider 也采用抽象：

``` typescript
export interface ModelProvider {
  generateText(request: GenerateRequest): Promise<GenerateResponse>;
  generateObject<T>(request: GenerateObjectRequest): Promise<T>;
}
```

Community 使用用户配置的模型；Cloud 使用平台配置的模型服务。AI Runtime
不需要感知部署版本。

------------------------------------------------------------------------

## 7. Connector Protocol 归属与要求

Connector Protocol 必须放在 Public
仓库。它是用户环境与平台之间的基础通信协议，不是 Cloud 私有功能。

协议至少定义：

-   Connector 注册与配对
-   身份认证、凭证轮换
-   心跳与在线状态
-   版本协商
-   数据源列表与授权
-   Schema 获取
-   SQL 查询与执行
-   任务取消、超时和状态同步
-   结果与错误码
-   防重放与任务签名

Cloud Broker 和 Community Local Broker 分别实现服务端。Go Connector
只理解公开协议，不感知 Tenant、Billing 等 SaaS 概念。

## 8. 技术栈基准

  层           技术
  ------------ -------------------------------------------
  Web          React + TypeScript
  UI           Tailwind CSS + shadcn/ui（Base UI），按需使用 TanStack Table
  API          NestJS + Node.js LTS
  AI           Vercel AI SDK + 可插拔 Provider
  平台数据库   MySQL（当前本地测试 26.7.0；8.0 兼容性待验证）
  ORM          Prisma
  Connector    Go
  MCP          官方 MCP SDK，按运行时选择实现
  参数校验     Zod
  实时事件     SSE；Connector 长连接采用经验证的安全传输
  Monorepo     pnpm + Turborepo（TypeScript 部分）
  Go 工程      独立 Go Module

用户已认可上述前端组件方案作为开发基线。具体版本、依赖兼容性、开源许可证及升级流程尚待验证；当前尚未安装或实现。共享基础 UI 和设计 token 应跨 Community 与 Cloud 复用，业务权限和数据操作留在各自业务边界。具体组件维护及验收要求见 `07-界面与交互规划.md`。

## 10. 开发验收标准

### 仓库边界

-   [ ] Public 仓库可独立构建。
-   [ ] Private 仓库通过版本化依赖使用 Shared Core。
-   [ ] Shared Core 不依赖 Cloud 模块。
-   [ ] Connector Protocol 位于 Public。
-   [ ] Community 不依赖 Cloud API。
-   [ ] 两个仓库的 Prisma Schema 独立。

### Community 独立运行

-   [ ] 无需 SaaS 账号。
-   [ ] 无需 Cloud 密钥。
-   [ ] 可配置用户自己的模型。
-   [ ] 可连接自己的 MySQL，默认只读；受控写入需通过独立安全验收。
-   [ ] Connector 可独立运行。
-   [ ] Remote MCP 与 Local MCP 可独立运行。
-   [ ] 核心功能不依赖商业授权服务器。

### 发布质量

-   [ ] 全新 Git Clone 可构建。
-   [ ] Docker Compose 可运行。
-   [ ] LICENSE / NOTICE 完整。
-   [ ] 安全测试通过。
-   [ ] 依赖许可证审查通过。
-   [ ] SBOM 已生成。
