# 第七阶段实施与审核记录

**状态：开发与测试完成，待用户审核，未验收。**

## 阶段范围

交付查询结果展示及截断、执行状态，会话和执行历史，保存及重新打开查询、分析与图表定义，授权范围内的连接、查询、安全事件审计，以及经用户选择的结果导出。第七阶段按完整范围交付并审核，不以 MVP 缩减。现有只读限制、Connector 最终授权和发送模型前确认继续生效。

## 已确认的数据处理规则

- 对话问题和 AI 回复可保存在本机平台数据库，管理员可以删除；界面须说明内容可能包含业务信息。未确认具体期限前不设自动过期删除，管理员可主动删除。
- 保存查询时保存 SQL 定义，不持久化参数值；重新执行前重新填写参数。SQL 本身可能包含字面量和敏感信息，保存前明确提示，审计不复制 SQL 或参数。
- 管理员可主动导出当前结果，导出前明确提示其可能包含敏感数据；默认不永久保存完整原始查询结果。
- 原有用户数据库不执行修复、重置或未经明确授权的迁移。迁移和功能先在已核验身份的专用隔离实例、使用虚构数据验证。

## 采用的现成方案

- [TanStack Table](https://tanstack.com/table/latest/docs/framework/react/quick-start) 9.3.1 提供表格状态、排序及分页；与项目 React 19 配合验证，MIT 许可。数值比较使用精确十进制文本比较，避免先转换为浮点数。
- [Recharts](https://github.com/recharts/recharts) 3.10.1，MIT 许可，采用柱状图和折线图；配套 react-is 19.2.0。只展示实际返回的每行数据，不隐含汇总；最多 500 行，无法安全表示的数值、二进制和失效字段拒绝绘图并保留精确表格。组件、类型和实际渲染均已验证。
- 保持现有 AI SDK、Zod、Better Auth 与 Connector 能力；保存或重新打开定义不赋予查询权限，执行前仍重新确认当前工作空间、数据源绑定及 Connector 本地字段授权。
- 如提供 CSV 等电子表格可打开格式，必须针对 [OWASP CSV 注入风险](https://owasp.org/www-community/attacks/CSV_Injection)进行格式和安全测试；同时明确数字精度、编码、转义及可能的表格软件差异。

## 开发与审核顺序

1. 建立第七阶段领域契约、显式迁移、数据归属及删除边界；验证仅在隔离库迁移，重启不自动改库。
2. 完善结果展示和主动导出，覆盖空值、二进制、时区、行/字节截断、精度、取消与失败；避免将截断结果呈现为完整结果。
3. 实现本地会话与执行历史的创建、分页和查看；会话/定义可软删恢复，执行/审计元数据只读保留，错误或取消不伪报成功。
4. 实现查询、分析与图表定义的保存和重新打开；参数重新填写，重新执行经过当前授权检查；验证结构变化、解绑、撤权及跨工作区访问。
5. 实现必要审计事件的记录与授权查看；不写入密码、令牌、完整结果或敏感原始参数，覆盖连接、查询和安全事件的成功与失败。
6. 完成界面、自动化、隔离数据库及实际 Connector 联动测试，记录测试结果、已知限制和用户审核结论；未经用户确认不得标为已验收。

## 当前进度

### 已实现的功能

- 会话：成功模型回复后自动本地保存，名称可修改；历史分页、重新打开、软删和恢复。保存失败保留本页内容，可核对不确定结果；多标签页修订冲突不覆盖他人内容，可另存新会话。重开会话不自动调用模型，继续对话仍须确认发送范围。
- 保存查询/分析/图表：显式提示后保存 SQL、说明、参数类型和可视化定义；不保存参数值或原始结果。重开读取最新定义并清空参数，空文本也须明确选择；当前数据源和 Connector 权限重新核验，结构变更不绕过检查。定义支持更新、另存、冲突保护、软删和恢复。
- 结果：表格分页和精确排序，NULL、Base64 二进制及 UTC 提示；柱状/折线和字段选择；明确行/字节/单元格截断。图表只基于当前结果，不自动查询、汇总或生成数据。
- 执行历史：服务端记录排队、运行、完成、失败、取消、过期、未知，以及可用的总耗时、行数和截断原因；不包含 SQL、参数或结果单元格。完成终态独立于结果内存保留，清理结果、解绑、撤销不把成功改成过期/取消。API 重启将旧未确认任务记为未知，不自动重跑；旧请求 ID 不可借内存清理再次执行。
- 审计：固定事件模式覆盖连接配对/诊断/轮换/撤销、数据源操作、工作区归档恢复、模型调用、查询与内容变更、可归属的权限拒绝、结果导出请求。内容变更与查询关键审计在同库事务提交；其他事件经本地持久队列重试，稳定事件 ID 防止不确定提交后重复写入。界面显示存储健康和待写条数。
- 主动 JSON 导出：用户明确确认后，服务端重新核验绑定并记录导出请求，前端再核对当前结果及组件范围才下载。保留小数文本、空值、二进制和截断信息；不输出 CSV。导出审计仅证明请求获准，不能证明文件已写入设备或以后如何传播。

### 组织、授权与迁移

`history/model.ts`、`store.ts`、`routes.ts` 与 `audit.ts` 分别负责严格内容模式、持久化/版本事务、HTTP 边界与审计投递。历史存储只拥有 `history_entry`，通过数据源公开接口获取当前绑定和工作区锁；依赖边界检查包含禁止历史模块导入数据源内部实现的规则。查询编排经 `QueryJournal` 端口提交最少元数据，不把内存结果作为审计内容。

005 显式迁移新增 `history_entry`，归属不可改变，50 条数字序列游标分页，修订号进行并发更新检查。启动核验迁移版本、校验和及实际表结构，未记录的部分 DDL 保留并拒绝启动，不自动清理或修复。启用条件为 `ENABLE_STAGE7_HISTORY=1` 且第三、第四、第六阶段全部启用；关闭第七阶段不后台继续记录其数据。

测试和演示只使用已核验 `@@port=13307` 及专用数据目录的隔离实例。随机测试库/账号测试后清理；已有演示平台库仅显式应用 005、保留原管理员/工作区/数据源。没有修复、重置或迁移用户原来的 3306 数据库。两项此前依赖固定过时测试库的用例已改为创建当前结构的随机隔离库，没有修复该固定库。

### 当前限制

- 单实例、本地管理员范围；会话和 SQL 定义明文存在本机平台库，软删仍可恢复，不等同物理擦除。数据库、备份和运行目录须限制访问；未约定自动过期，不擅自定期删除。执行与审计元数据当前只读保留。
- 审计不是防篡改法证日志。外部模型或 Connector 状态文件提交，与审计入队之间无法跨系统原子提交；这一步发生磁盘故障或进程崩溃仍可能缺少最终事件。已提交操作保留真实结果，已发现的磁盘故障暂停后续界面写入。审计时间为记录入库时间，队列延迟应结合健康状态判断；匿名失败不能伪造为某位管理员的事件。
- Windows 使用文件刷新和原子替换；目录 `fsync` 不可用，POSIX `0600` 不替代 Windows ACL。损坏文件不会自动删除或重置。
- 仅在本机 MySQL 26.7.0 与本地模拟 OpenAI 兼容模型验证；MySQL 8.0 和真实外部供应商仍须独立验证。只读、单表和现有 SQL 限制不因保存功能扩大；多表、聚合、受控写入不在本阶段开放。
- 图表最多 500 行；无法保持安全数值精度时要求查看表格。生产主 JS 约 969KB（gzip 293KB），构建有大包提示，尚未完成图表按需分包优化。
- 生产依赖审计仍报告此前已记录的 MySQL2 两项、Multer 一项告警（2 高、1 中），本次未新增表格/图表相关告警。按此前用户要求保留，未擅自升级；详见依赖审计记录及 [MySQL2 高危公告](https://github.com/advisories/GHSA-3f6p-5ww8-9rcr)、[MySQL2 中危公告](https://github.com/advisories/GHSA-rgwj-5xj2-c3m3)、[Multer 公告](https://github.com/advisories/GHSA-q7qp-rjg7-q26m)。不能据此宣称生产安全审核通过。
