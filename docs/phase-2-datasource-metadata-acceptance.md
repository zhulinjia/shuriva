# 数据源结构理解：验收说明

本阶段让用户查看数据库结构、补充业务含义并控制提供给 AI 的结构。原数据库通过只读连接读取；业务说明、用户确认的关系和范围配置加密保存在 Shuriva，自定义说明不会写回原数据库。

## 验收环境

浏览器验收服务运行在 `http://127.0.0.1:4318`，账号 `admin`，密码 `shuriva`。访问 `http://127.0.0.1:4318/test-info`，复制其中的 `metadataPath`，作为测试用 SQLite 数据库路径。

示例数据是虚构数据；已有数据源、工作台及模型配置会保留。自动化测试使用模拟模型，手工生成时仍会使用你选择的模型，可能调用真实服务。若服务未运行，请先确认本机验收服务已启动。

## 操作步骤

1. 登录后点击左侧「数据源」。在「添加数据源」填写名称、选择 SQLite，粘贴上述路径并点击「测试并添加」。已有可用数据源也可以直接点击「查看结构」。
2. 点击示例库的「查看结构」，左侧选择 `orders`。检查 `id` 主键、字段类型、非空状态和关系 `orders → customers`；该关系应包含 `tenant_id` 和 `customer_id` 两组字段，并标记为「数据库定义」。
3. 给 `orders` 填写表的业务说明，再给 `amount` 填写字段说明。点击「添加关系」，选择 `customers` 和关联字段，填写关系说明后点击「确认添加关系」。页面应将其标记为「用户确认」。
4. 在「提供给 AI 的结构」选择「仅选择的表和字段」，取消 `amount` 的勾选。切换到其他表时应能看到各自的选择数量。点击「保存说明与范围」，按钮附近应出现保存成功信息。
5. 刷新浏览器，重新进入示例库的 `orders`。确认说明、用户确认关系及字段选择仍然存在。编辑说明后先返回数据源列表，再进入该库，未保存的输入应仍在；确认后保存。
6. 将 AI 范围切换回「全部读取到的表和字段（默认）」并保存，可恢复该数据源的默认上下文范围。选择范围控制的是发送给 AI 的结构，不是数据访问权限。

## 当前边界

- SQLite 没有内建的表和字段注释，本示例展示用户补充的说明；PostgreSQL / MySQL 注释和关系读取代码尚未在真实对应数据库上验收。
- 默认情况下，选中数据源的全部已读取结构会提供给模型。可改为指定表和字段；名称、注释、业务说明、关系说明和用户输入可能发送给模型。系统不主动发送数据库记录样本，用户自行写入的信息除外。
- 模型只能生成受控的单表查询。关系仅作理解用途，不代表已验证数据完整性，也不表示已支持 JOIN 或跨库关联。
- 每个数据源最多读取 500 个表或视图、10000 个字段和 10000 项键。结构过多会显示警告；表或字段不完整时不能用该数据源生成工作台。权限不足或数据库功能限制可能导致关系、注释读取不完整，页面会提示。
- 不同数据源的配置相互独立；当前工作台引用了未提供给 AI 的表或字段时，修改请求会被阻止。该范围不是 Cloud 的字段权限或行级权限。
- 数据库结构改变后，对应的旧说明与用户关系仍保留；无法匹配的关系不会提供给 AI。并发编辑发生版本冲突时，本地输入会保留，可复制后选择读取最新配置。
- 该环境验证了真实 SQLite 和模拟 AI；真实 PostgreSQL、MySQL 和真实模型的端到端验证留待后续阶段。
