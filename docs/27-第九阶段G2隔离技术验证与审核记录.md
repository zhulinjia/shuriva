## 3. 关键适配与证据

### 3.1 OAuth 与现有管理员认证

实测现有认证工厂的真实登录会话可用于候选 OAuth 组件；公共原生客户端通过精确回调登记和 S256 换取访问令牌。资源、签发者、权限、PKCE、回调、授权码重放、过期及被禁用的注册/授权路径都有正负向测试。

访问令牌使用 opaque/hash；平台测试表不含原始 OAuth token、授权码、明文密码或 JWT 私钥。公共客户端对标准内省端点的未认证调用被拒绝；同进程使用 SDK 文档公开的 `getOAuthProviderApi(...).requireActiveAccessToken`，再执行应用资源与授权判定，不自行编写 OAuth 或读取插件内部表来代替校验。

Windows MySQL 的表名折叠导致 SDK 默认驼峰模型核验失败，现通过显式 lower_snake_case 物理表映射解决，未修改数据库服务设置。

发现并复现 SDK 可空会话关联的限制：令牌原先关联真实会话，退出/终端恢复删除会话后，关联变成 NULL，SDK 仍可返回 active。独立应用授权保留非空的原审批会话引用，使用认证模块新增的 `authSessionReferenceDeadline` 事务内 `FOR SHARE` 核验；授权与会话在同一连接持锁判定，拒绝孤立令牌和会话删除竞态。原布尔端口继续由认证模块维护，不让 MCP 适配器直接读取认证表。

授权代码另绑定批准时的授权世代；交换时不能借当前世代升级旧批准。SDK 缓存的同意记录也保留原来真正批准的世代，不能因授权码新签发就升级；世代变化后须显式重新同意。审批流程先锁定本模块授权世代并拒绝失效尝试，再调用 SDK 的公开同意端口；旧世代不能在绑定容量失败等路径里污染当前 SDK 同意缓存。未交换的代码绑定过期后先清理再核验容量，仍有数量与一次性消费约束。

最终令牌判定在应用授权与审批会话持锁期间，再调用认证库公开 API 核验，并在异步等待后检查实际令牌期限。这样 SDK 撤销发生于等待期间会被最终观察发现，不以早先的 active 结果当缓存。SDK 与授权适配器各使用一个有界、同样受实例 guard 保护的连接池，避免授权锁持有全部连接而阻塞最后的认证查询；八个并发观察与真实 SDK 撤销的测试均拒绝放行。有效性结论对应最终观察点，不承诺观察之后的撤销能消除已经开始的操作。

锁不能阻止时间流逝。授权观察携带认证模块给出的真实会话期限，领域判定将其与授权期限取最小值，在最终认证后、事务提交等待结束后分别检查；OAuth 令牌期限也在异步授权后重查。真实等待跨过审批会话期限的用例明确断言等待钩子已到达，避免在更早的失败路径误判通过；领域用例分别模拟提交等待跨过授权与会话期限。

真实 MySQL 用例分别证明“会话仍有效而世代变化”“已批准代码在世代变化后才交换”“SDK 校验后删除会话”均不能绕过应用授权。现有改密流程实际会替换/撤销原审批会话，测试如实检查会话失效，另用独立用例证明世代撤销。

### 3.2 传输、网络与超时

- HTTP 与 stdio 实测官方客户端的 2025-11-25、2026-07-28 路径。复用 SDK 的标准协议支持；未编写本项目旧版兼容层，也不把 SDK 测试当作 Claude Code/Cursor 等客户端已验收。
- SDK 前限制实际字节、深度、节点、参数、压缩、帧截止、Header/请求体截止、并发和速率。授权自身亦有截止与独立容量，晚到工作在真正结束前保留配额；不通过释放仍在运行的工作掩盖资源泄漏。
- 网络目标精确到 URL（包含查询参数），私网批准逐地址核验并固定连接。拒绝未批准来源、混合非法 DNS、私网转公网、云元数据、重定向、跨凭据目标的自定义密钥头和 Cookie。
- 实际 SDK 使用注入的受限 fetch；原始适配器错误不向工具结果回显。工具失败可为 HTTP 200 / `isError:true`，后续产品状态机必须检查工具结果。
- 真实取消通知会到达处理器，但不能证明操作从未开始；等待中撤销阻止结果披露，测试不自动重放调用。
- 响应和实际工具工作共同持有原请求的执行配额。断线只结束响应份额，忽略取消的工具在真正结束前仍占用原来的配额；四个断线工具占满后拒绝新请求，结束后恢复的真实 SDK 测试通过。

完整流程的一次重跑出现 48/50：两项 HTTP 测试在进入撤销/取消逻辑前被 Node Fetch 的 `bad port` 拒绝。核对本机 Node 内置端口拦截表及 [Fetch 端口规则](https://fetch.spec.whatwg.org/#port-blocking) 后，测试监听器改为直接绑定 [IANA 动态/私有范围](https://www.iana.org/assignments/service-names-port-numbers/service-names-port-numbers.xhtml)（49152–65535），占用/禁止绑定时最多尝试 16 次，不先探测空闲端口，也不修改 Fetch 的拦截策略。新增真实 Fetch 成功、占用预算与不影响已有监听器的两项测试。端口修订后完整 52/52；后续六项授权与容量修订加入回归后，最终单命令完整流程为 58/58。早先失败保留在本地证据，不算通过。

### 3.3 本机执行宿主

私有管道用真实 Go 与 Node 子进程测试握手、帧上限、崩溃和上下文取消，未创建公共控制端口。它是运行时交接验证，尚不是 Go Connector 的产品侧集成。

Windows Job 测试先建立拥有关系再启动固定 Node/SDK 程序，broker 保留唯一长期句柄。宿主强制退出和正常退出均回收实际子孙进程。目录及其祖先的 reparse point 被拒绝；测试证明 broker/worker 不会通过匹配前缀的 junction 写出拥有目录。Node 路径由实际测试进程传入，不假设固定安装目录。最小环境保留经对照验证必要的 Windows 系统变量，未继承数据库连接或管理员密钥。

这些机制用于受信程序的生命周期管理。同用户进程仍共享系统用户权限；独立客户端的 OS 身份隔离与分离执行主机未验证，保持禁用，不以 PID、程序名或凭据引用假称身份隔离。

## 6. 迁移草稿与未完成产品工作

[OAuth DDL 草稿](../research/mcp-g2/schema/oauth-provider.generated.sql) 来自 SDK 在隔离库中的实际生成/运行结果；[最小授权草稿](../research/mcp-g2/schema/mcp-grants.sql) 已验证事务、不可丢失的会话引用、令牌哈希唯一性及并发世代更新。两者不自动注册到平台，不包含用户数据，也不是完整 MCP 产品迁移。
