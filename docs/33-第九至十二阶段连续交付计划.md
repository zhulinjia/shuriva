# 第九至十二阶段连续交付计划

用户授权剩余阶段连续推进，不再等待中途人工审核；每阶段完成后由未参与该阶段实现的独立 Agent 审查代码，确认问题修复并通过适用测试后推进，最后统一交付。用户随后明确取消第10阶段桌面软件（此前忘记从范围删除），当前仅推进第9、11、12阶段，不安装桌面工具链、不开发或打包桌面软件。该授权不允许将未验证功能标为完成、不允许对原数据库试验，也不自动授权发布公网服务、创建付费订阅或收费。

## 实施与审查

| 12 | 安装运维、配置、健康与日志、备份恢复、许可证/SBOM、发布和兼容性验证 | 已有候选和 Cloud 原生审查证据保留，当前本机验收及待办见 [发布验收与 Cloud 后续实施](41-发布验收与Cloud后续实施.md) |

Community 和 Cloud 代码保持独立。若当前工作区内暂存独立 Cloud 仓库，使用已被 Public Git 忽略的 `.private/`；不得从 Community 导入该路径，不自动上传或发布。Shared Core 使用公开版本化接口，禁止复制 Community 内部实现到 Cloud。

未确认的收费套餐、价格和真实支付供应商不能凭猜测接入。先实现供应商端口和本地隔离验证，真实收费保持关闭；需要真实外部身份、签名凭据或其他机器才能验证的项目明确记录，不伪称通过。

数据库操作只使用新建并核验身份的独立实例；所有迁移仅对隔离目标演练，原库不连接、不迁移、不清理。真实断电、实机休眠和物理磁盘故障继续按用户已决定的范围排除。

审查区分独立 Agent 评审、项目要求的 Codex 原生 Review、自动化测试和真实环境验证，不相互替代。既有 Git 工作区含前序未提交修改，不擅自提交、重置或清理，不将 HEAD 当作本轮干净差异基线。

最终报告必须列出每阶段实现、独立审查、测试、可试用入口和剩余限制。阶段尚未结束时不使用“完成”状态。

当前构建的测试、独立审查及发布证据见 [连续交付验证与审查记录](39-连续交付验证与审查记录.md)，未验证环境和未完成审查按实际状态保留。
