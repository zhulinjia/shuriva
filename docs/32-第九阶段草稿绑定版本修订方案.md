# 第九阶段 MCP 草稿绑定版本修订方案

状态：**绑定代次修订已实现，隔离验证及独立评审进行中，尚未整体验收**。实现取舍和实际验证结果见 [第九阶段绑定代次实施与隔离验证](36-第九阶段绑定代次实施与隔离验证.md)。本文件不授权对用户现有数据库执行迁移。默认装配仍关闭 MCP 草稿；只有完整核验独立绑定身份迁移的显式隔离装配才启用来源预览。正式写入门禁继续关闭。

## 问题与已确认事实

草稿接收和后续管理员预览之间，数据源可能解绑、改绑 Connector 或重新绑定。现有 `workspace_data_source` 以工作区与数据源作为主键，仅有 `boundAt` 毫秒时间，没有可证明唯一的绑定代次。即使 Connector 和时间相同，也不能推断中间没有发生解绑重绑。单进程计数、名称和时间差均不能作为权威版本。

外部调用、浏览器提交的来源编号和模型输出都不是授权依据。新方案应让服务端对实际绑定、Connector 和代次做匹配，且在预览异步执行前后均核验。原授权撤销后，已接收草稿的管理员可以独立操作，但不因此放弃对数据源绑定、用户会话、Connector 和本机写策略的检查。

另一个独立限制是数据库 `COMMIT` 发出后发生超时或连接丢失，调用方无法仅凭超时确定事务是否提交或提交时刻。当前回执核验只持锁读取，持久调用状态保留 `handoff_unknown`；同一进程只有在正常收到数据库事务完成结果并再次通过时限检查后才可建立短期内存来源证明。进程重启、检查失败或提交结果未知时不重放草稿，也不把服务端发送完成描述成浏览器接收或人工处理。**正常接收后外部状态仍显示 unknown 是明确的当前限制，是否需要可恢复的持久成功状态须另行设计和审核。**

## 当前绑定版本模型

1. 通过复合外键引用权威绑定的 `source_binding_identity` 侧表保存不可由前端选择的随机 UUID 版本。每次新建绑定在同一数据库事务中产生新版本；解绑级联删除该身份；重新绑定即使使用同一 Connector 也必须得到新版本。唯一约束防止重复，冲突导致绑定事务失败，不覆盖其他绑定或使用时间戳代替版本。
2. 数据源访问适配器在核验工作区、数据源所有权和归档状态后，返回 Connector 标识及真实绑定版本。缺失、格式错误、结构未验证或无权访问均失败关闭。
3. 草稿提交时在真实绑定锁与授权检查下捕获 Connector 和版本，作为内容承诺的一部分；管理员查看、领取及接收时重新核验。接收后的内存来源证明仍绑定真实管理员会话、工作区、数据源、Connector、绑定版本和原计划承诺，不能由浏览器声明代替。
4. 预览应用用例在调用 Connector 前核验版本和 Connector；在异步预览返回、持锁保存预览前再次核验同一版本和 Connector。期间解绑后重新绑定，即便复用了相同 Connector，也必须拒绝该来源预览。Connector 自身的目标身份、权限、策略和阶段 8 所有检查不变。
5. 已验证来源的预览审计记录原调用、预览编号和计划是否改变；变化只表示当前计划与接收计划的承诺不同，不推断修改者意图。不得把来源编号当作执行授权。来源证明不存在、被淘汰或进程重启后失效时，不发送预览到 Connector。
6. `mutation_preview_binding` 保存预览绑定承诺，确认、首次领取和签发许可均在真实来源事务锁内复核。它不代替目标身份、完整快照或阶段 8 既有授权。无代次的迁移前预览保留原数据，但不能猜测来源或获得新的执行授权。

## 显式迁移设计及中断恢复

使用新的独立迁移 `009-binding-identities.sql`；不修改已执行的阶段 3/8 迁移、校验和及业务表形状。命令 `db:migrate:bindings` 必须显式指定目标数据库，先验证既有结构，并在维护窗口停止所有可能创建或删除绑定的应用实例；不能用删除、重建或清空业务表替代迁移。数据库及备份由其管理员决定，本次只在独立实例验证，不操作现有库。

可重入步骤如下；MySQL DDL 会隐式提交，不能把全流程假定成一个原子事务：

1. 获取目标数据库专用迁移锁，记录或核验步骤状态；若存在不符合预期的列、索引或约束，立即停止并报告，不能覆盖。
2. 只创建缺失且定义已知的身份、预览映射和独立版本记录表；完整核验列、默认值、索引、同库外键和动作，拒绝未知触发器或 CHECK。侧表版本从创建起非空，不修改阶段 3 原列。
3. 在停止业务写入的前提下，以最多 100 行的批次锁定尚无身份的真实绑定，逐行生成随机 UUID 并在事务内插入身份；不变更原主键、时间或其他业务字段。已回填行保留原值；中断后重新核验，从缺失身份继续。
4. 验证版本格式和唯一约束。异常、重复或未知结构立即停止，不覆盖已有值，不为无来源预览补写代次。
5. 校验阶段 3/8 和新增版本结构，记录独立迁移版本及 SQL 校验和。中断后以实际结构和数据重新判定；不能仅根据客户端异常假定 DDL 或批次事务成功或失败。
6. 仅在完整迁移及应用调用链均已验证后，允许具备该能力的受控装配启用来源预览。所有新绑定必须在原绑定事务内写入新 UUID；运行时不得在版本缺失时临时猜测或自动补写。

具体实现、故障注入和恢复说明见上述实施记录。未安装模块时保留无关只读/恢复能力，新预览/确认/首次领取/许可失败关闭；能力接口返回 `binding_identity_required`，运行时不临时补写身份。对现有库的实际执行、数据备份和维护安排须按用户当时的明确授权进行。

## 隔离验收与评审条件

- 仅在新建并核验身份的独立测试实例中运行迁移。验证带多条现有绑定的数据与其他列保持不变，重复迁移不变更已分配版本；注入每个 DDL、回填和校验步骤中断，验证可恢复或明确失败关闭。
- 覆盖同 Connector 解绑重绑、换 Connector 重绑、迁移前后的已有绑定、新绑定、并发操作以及预览请求开始后发生重绑；旧来源必须在调用或保存预览之前被拒绝。
- 验证未迁移、部分迁移、版本缺失/格式异常/重复、结构和索引不匹配时全部失败关闭；覆盖不同管理员会话和工作区/数据源。
- 对回执事务分别注入行锁等待、授权到期、事务提交等待、提交响应丢失及进程重启；提交结果不确定时只报告 unknown，不能重发草稿或生成可用的来源证明。
- 在独立实例和真实 Connector 上重新完成浏览器领取、真实预览、管理员单次确认、MCP 同编号重试及执行/回执数量验证；此前旧实现的浏览器贯通结果不代表修订版通过。
- 运行项目检查及安全测试，按 `auto-code-review` 完成针对实际变更的 Codex 原生审查并核实发现；明确 MySQL 8.0 等未实测范围。用户已排除的真实断电、休眠及物理磁盘故障不重新列为当前阻断项。
