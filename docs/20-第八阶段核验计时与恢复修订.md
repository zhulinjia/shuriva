## 1. 三个根因与设计变化

| 根因 | 当前设计 | 权限及行为边界 |
| --- | --- | --- |
| MySQL 目录按查询者权限过滤，空集合可能漏掉隐藏依赖 | DBA 安装固定目标、无输入 SQL 的 `SQL SECURITY DEFINER` 核验过程；不可登录的 definer 持所需完整目录权限，运行账号仅可调用该固定过程 | 不将 TRIGGER、REFERENCES、全局业务 SELECT 或 DDL 权限交给运行账号；不安装 helper 的来源保持只读 |
| 普通 Go 进程单调钟不能作为跨休眠、跨重启的许可依据；普通进程不能承诺硬实时发送 | Windows 研究适配器读取官方、包含休眠的 interrupt time；固定首次请求前截止，旧许可不恢复 | 截止约束是持锁的单次 Commit 交付资格判定；不承诺网络发送或数据库提交完成发生于硬实时截止前 |
| 平台登记、本机日志和业务提交分别落盘，合法旧备份不能证明“没执行过” | 增加目标实例内的专用回执表，与业务 DML 同一个 InnoDB 事务提交；双端每次启动建立新的内存世代，旧任务永不恢复执行 | 回执只帮助查证结果，缺失回执不授予重试资格；源业务表不增加字段或触发器，运行账号不负责安装或迁移 |

以上是对 G1 的明确修订，尤其替换原“不在数据源安装任何控制表”的假设。受信 DBA 的安装与维护是单独边界，不能藏进普通查询、连接测试或页面确认。此次授权只用于新实验实例；没有把安装方案用于用户原数据库。

## 2. 完整核验的契约

核验包必须绑定服务器身份、catalog、目标基础表、支持版本、安装世代、固定过程和预期授权集合。写事务先取得目标 MDL/行锁，再通过同一事务连接读取目标定义和隐藏依赖证明，锁持有至 Commit/回滚。直接用普通账号读取 `information_schema` 或复用旧 Definer view 均不合格。

固定过程不接受表名、SQL 或任意筛选，不执行 DML；返回的目录结果必须连同身份、授权证明、类型及结果完整性一起验证。每个结果集先验证完整列形状，包括空结果；过程在 definer 上下文返回自身真实 SHOW CREATE，无需给调用方全局 SHOW_ROUTINE。过程定义、创建 SQL mode、字符集和排序规则必须匹配由受信安装流程产生的本机清单；清单绑定已审核发布模板，不能在运行时把目标返回的任意新定义自动登记为可信。

权限撤销、partial revoke、角色、额外权限、未知结果形状、数据库错误或安装不符均拒绝。除直接授权外，还须核验 mandatory roles、自动激活角色设置和当前角色；不能把 SHOW GRANTS FOR CURRENT_USER 的两行输出误当作完整的无角色证明。触发器/不允许的外键等确实存在时，结论是该表不可写，而不是绕过它们执行。

DBA 能替换过程、权限和数据库内容，本设计不声称抵抗恶意 DBA。安装和授权维护必须先关闭写入口、排空事务并更换安装世代；普通运行账号不能进行该维护。目标 MDL 不锁住 GRANT，不能用 MDL 冒充权限世代锁；授权前后相同也不能普遍检测 A→B→A。无法保证该维护契约的来源不开写。

## 3. 时间契约

首次许可请求前读取系统 interrupt time，并在内存中绑定 API/Connector 当前启动世代、挑战、执行及承诺，确定不可延长的截止。响应延迟、排队、重取、网络重连和本机持久化消耗都计入预算；适配器不可用、时钟倒退、读取失败、超时或绑定不符均拒绝交付。重启不从 UTC 或序列化读数重建旧截止。

普通用户进程可在任意指令后被系统暂停，因此不能证明“检查时未超时”必然意味着稍后网络发送仍未超时。当前契约明确以策略锁内、同步 commit_intent 落盘后的最终系统计数采样作为一次 Commit 交付资格的线性化点，剩余预算须严格大于 100ms 保留量；保留量不是最坏调度延迟保证。交付前失效则回滚，交付后即进入可能已提交阶段，不能因随后到期或暂停就宣称未提交。取消/撤销顺序以同一交付边界判定。

Windows API 的休眠语义依据官方文档；真实 API 读取、普通等待和注入暂停测试分别记录。注入大幅前进不等同真实电源转换。此次不让用户电脑休眠、不改系统时钟或电源设置，也不将这台电脑的结果扩展为 Linux/macOS 或 MySQL 8.0 支持。

## 4. 持久回执与恢复契约

目标回执与业务表必须在同一已核验实例、同一连接、同一 InnoDB 事务中；禁止独立提交回执后再执行 DML，或业务提交后补写回执。回执唯一键绑定不可复用的执行编号，内容含作用域、不可枚举承诺及世代等必要元数据，不存参数、SQL、原始行或凭据。运行账号不能更新、删除或直接读写其他范围回执，安装账号与运行账号分离。固定回执过程自身不能独立检查调用方是否同时执行正确业务 DML；受信 Connector 编排属于安全边界，不宣称能抵抗已被攻陷、可直接写业务表的 Connector。

平台事务登记仍是确认唯一消费的权威；bbolt 仍负责本机持久防重与负载，不变成分布式事务协调器。开始目标操作前，SQL 行锁读取真实登记，逐字段比较本机不可变记录、作用域、承诺及双方运行世代；先同步消费本机尝试，再提交 SQL 消费。任一步失败均不派发 DML，已消费尝试不因另一存储回滚而重新获得资格。目标回执是提交事实的补充权威。Commit 应答丢失或本机终态落盘失败时，只查原编号；匹配且通过完整性校验的原回执可证明该事务提交，缺失、冲突、不可达或无法证明时仍未知并冻结。

每次 API 或 Connector 启动都生成新随机、仅内存的运行世代；重启前的确认、队列任务、预览和提交许可只允许查证，不允许重新执行。新写入必须来自本次双方运行世代内的新预览与人工确认；恢复认证或读取旧日志不能补发旧执行许可。平台和日志同时回退也不能让带旧运行世代的消息获得新执行资格。

仅改变内存世代还不足以排空数据库中已开始的旧事务。目标控制表因此增加独立的持久执行世代门：每笔目标事务通过固定过程先对该门 `FOR SHARE` 并核对绑定世代，锁保持至业务/回执事务结束；恢复身份通过另一个固定过程 `FOR UPDATE` 轮换世代。独占屏障须等待旧事务结束，超时就继续冻结，不能假装排空完成；轮换成功后，迟到的旧世代事务在业务 DML 前被拒绝。普通 writer 不能调用轮换过程。目标控制表、固定过程及其权限同样属于受信安装和结构准入范围，禁止触发器、隐藏副作用或混合引擎。

启动先冻结并完成目标屏障，再分页核对该范围的原回执和登记。即使两端旧备份丢失全部执行编号，也通过固定范围、每页最多 100 条的主键游标回执接口发现原编号；查证与列举不派发业务 DML、不重签旧许可。空列表不证明未执行，也不是解冻授权。新操作仅在屏障、完整性及当前授权核验完成后按新世代登记；未解决的未知仍按来源冻结策略处理。

世代门按受信安装清单确定的物理实例/catalog/控制 incarnation 共享，不以 workspaceId 或 sourceId 分开。不同账号和数据源别名指向同一 catalog 时必须共用同一门；不能分别安装互不关联的控制门后声称隔离。回执的查看范围另按当前管理员/工作区授权收紧。本轮验证同实例、同 catalog、同固定控制对象的两个受限账号，不证明自动发现任意代理、克隆 UUID 或不同部署的别名；无法确定唯一控制身份时不开写。

恢复适配器须通过固定范围只读端口读取目标当前门值，再以 expected/current CAS 轮换；不能从旧平台备份推断它，也不能用 NULL expected 绕过核对。读不到当前值或 CAS 冲突时保持冻结。本轮实验直接持有 fixture 当前门值，验证读取后 CAS 所需的数据库原语；正式当前门发现接口与恢复协调器留 G3 实现，不声称已有完整自动恢复服务。轮换身份的独立凭据也只留 Connector 所在环境的密钥存储。

如果业务库及回执也一并恢复到旧备份，旧回执缺失无法区分“从未提交”和“提交后历史被回退”。没有外部不可回退权威就不可能自动证明，设计不承诺这种自动恢复。数据库恢复必须停写、停止相关进程、进入维护模式并创建新的目标 incarnation；旧操作仍永不重跑。整机内存快照回退、在线替换数据库文件、恶意 DBA 不在自动恢复支持范围，禁止据此自动解冻；若产品要支持，需新增可信外部防回退权威并独立验证。

## 7. 当前结论与后续门槛

三项根因已有明确设计替代及当前 Windows/amd64、MySQL 26.7.0 的隔离可行性证据：完整目录通过受控固定过程取得，计时依据含休眠系统契约且限定可实现的交付语义，恢复以同事务目标回执、内存启动世代和目标屏障为依据，不再把可回退日志当作重试授权。

**本轮研究范围验证通过，不等于整个 G2/阶段 8 或正式写入已验收。** 本轮调整（目标控制对象、可信 DBA 安装维护、交付时限语义）应由用户复核后作为 G3 基线。G3 还需实现正式安装清单/凭据存储、完整授权器、当前门发现与启动冻结协调、签名协议和回执、真实认证/队列/恢复接口及 UI；G4 再做完整 W01–W64、真正分布式提交应答丢失、磁盘满/断电、支持平台电源转换及版本矩阵验收。MySQL 8.0、任意代理/克隆别名与整机快照恢复未获支持结论。

若要求所有权威与运行内存同时回退后仍能自动判定历史，必须另有不可回退的外部可信根；本设计明确不提供该自动恢复保证。未满足可信安装、目标唯一控制身份或恢复证据时保持关闭，不能靠人工把旧执行改名、删日志或降低断言继续执行。正式产品写入口继续拒绝，不自动进入 G3 或对用户原库安装对象。
