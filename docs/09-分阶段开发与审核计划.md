## 阶段审核办法

1. **开工前：** 根据本计划列出本阶段具体任务、界面状态、接口与数据变更、依赖和需要用户决定的问题；对阶段内方案作必要设计，不把待定问题当成已有决定。
2. **开发中：** 依照 `AGENTS.md` 维护边界和代码约束，涉及认证、权限、数据库或密钥时补充对应安全与隔离环境测试；界面随功能设计并覆盖正常、加载、空、失败和权限不足等适用状态。
3. **提交审核：** 提供可操作的演示入口或步骤、交付清单、测试结果与环境、独立视角代码/安全评审发现及处理、未完成项和风险。AI 评审是辅助，不代替自动化测试或人工判断。
4. **审核与修复：** 用户按阶段验收；反馈的问题在本阶段修复并重测，随后再次提交审核。只有用户明确认可且本阶段必需检查通过，才将其标为“已验收”并进入下一阶段；有未解决的必需问题时标为“待修复”或“受阻”。未经用户确认不将阶段标记为已验收。
5. **记录：** 每阶段维护状态、交付物链接、测试环境和结果、评审问题与处理、未决事项、审核日期和用户结论；不记录密码、密钥、完整连接串或敏感业务数据。

阶段状态统一使用：**未开始 / 进行中 / 待审核 / 待修复 / 受阻 / 已验收**。阶段 0 和阶段 1 已由用户确认验收；阶段 2 尚未验收。若用户明确要求调整范围或并行工作，记录影响后按新决定执行。


## 阶段 1：工程基础、管理员与工作区

**交付：**

- 对当前实现做代码与安全评审，处理已发现的问题；落实格式、静态检查、类型检查、构建、测试及模块依赖边界的适用门禁，并给出可重复运行方式。
- 将真实认证和工作区数据结构、设计草稿及迁移历史统一为可持续维护的单一来源；先为已有数据库制定保留现有管理员和工作区数据的迁移/前向修复方案，在隔离库演练。不会把现有草稿直接应用到开发库，也不清空已有数据。
- 完善本地管理员初始化、用户名登录、退出、修改密码和当前会话管理；明确错误提示、限流、过期与撤销行为。账号邮箱和验证/找回方式按实际能力明确，不假装已配置邮件服务。
- 完善工作区的创建、列表、切换、重命名和归档界面及服务端授权；明确归档后的访问行为。默认数据源绑定待阶段 3 实现，不在本阶段伪装为可用。
- 补齐登录、工作区和管理界面的交互状态、键盘可用性及移动窄屏的基本适配；保留对未开发工作台功能的明确标识。

**审核与测试：**

- 用户可按说明初始化、登录、修改密码、查看/撤销会话、创建/重命名/归档并切换工作区；重启后已保存的数据仍在。初始化重复执行不能创建第二个 Owner；错误密码和失效会话不能访问受保护接口。
- 按角色/所有者测试未登录、跨账号访问、会话撤销、跨来源写请求和异常输入；测试空、错误和不可用状态。多管理员和成员管理如未在本阶段确认，应保持不可用并说明。
- 在隔离库验证从当前表结构升级的迁移，检查已有账号、密码哈希、会话及工作区数据的保留和迁移失败的处理；提供备份及恢复/前向修复步骤。不得使用生产库做试验。
- 格式、静态检查、类型检查、构建、单元/接口及数据库集成测试有明确结果；记录本机 MySQL 版本。MySQL 8.0 未验证时标明，不用 26.7.0 结果代替。

**需要在本阶段确定：** Community 是否支持多个本地账号、工作区归档后的访问规则、密码找回方式，以及会话令牌数据库存储和限流的部署取舍；先给出可审核方案再实现。未经用户确认，不将这些待定项视为既定产品决策。

## 阶段 2：Connector 身份与通信

**交付：** Connector 与平台的版本化协议、注册/配对、连接状态、任务身份和有效期、凭据轮换与撤销、离线和版本不兼容状态；Connector 的本地安全存储及可观察的生命周期。明确协议所属模块和版本协商；不实现可绕过策略的任意 SQL 执行。

**审核：** 演示配对、上线、离线、重连和撤销；错误身份、不支持的协议格式、过期/重放请求及撤销后的新任务被拒绝；验证网络中断、并发、密钥不进入平台日志与普通配置。协议变更同步更新当前平台、Connector 和跨语言测试，不为未发布的旧版本保留兼容实现。

## 阶段 3：数据源与结构管理

**交付：** 在 Connector 所在环境配置 MySQL 连接与受限账号、测试连接和查看状态；数据源创建、工作区绑定/解绑与默认数据源；授权范围内的结构扫描、版本化快照与浏览。平台只保存非敏感选项和凭证引用。

**审核：** 用隔离的用户数据源演示连接、失败提示、绑定/解绑及结构扫描；验证未绑定/无权数据源不可访问、错误消息脱敏、旧快照在扫描失败时不被覆盖。使用单独受限账号，验证实际权限、MySQL 版本和连接参数；未经验证的对象或能力不得宣称支持。

## 阶段 4：只读 SQL 安全引擎

**交付：** MySQL 方言解析和允许列表、对象及字段授权、参数化执行、只读数据库账号和 Connector 独立校验；执行超时、取消、结果大小/行数限制、截断和脱敏状态。明确已支持的 SQL 子集与未知语法的拒绝规则。

**审核：** 在隔离 MySQL 上验证允许查询和拒绝多语句、写入、锁定读取、文件输出、可执行注释绕过及未知语法；覆盖跨工作区、字段/视图授权、参数、超时、取消和连接池清理。对未证明安全的语法失败关闭；写入入口仍关闭。验证范围及 MySQL 版本必须记录。

## 阶段 5：模型配置、AI 对话与查询计划

**交付：** 用户自配模型与密钥管理、模型状态和数据发送边界；对话页面与消息状态；基于获授权结构生成可解释的参数化查询计划，展示目标数据源和 SQL。模型供应商、密钥放置和发送数据的范围在开发前明确。

**审核：** 演示配置、失败、问题澄清、计划生成和安全校验后的只读查询；验证模型编造字段、提示注入、未授权请求和敏感内容处理，确保系统提示词与模型输出不能绕过程序权限与 Connector 校验。测试断流、超时和错误，未得到真实结果时不得显示成功。

## 阶段 6：语义与敏感数据

**交付：** 工作区与数据源范围内的业务实体、字段说明/同义词、关系、指标和敏感级别，结构变化/失效提示，以及 AI 查询计划对已授权语义的使用。

**审核：** 验证跨工作区或数据源引用被拒绝、结构变化后失效提示、语义权限不扩大数据库权限；演示版本更新和错误恢复，并检查发送模型前的敏感数据策略。

## 阶段 7：结果、历史、可视化与审计

**交付：** 查询结果表格、状态、截断说明、会话与执行历史；保存查询、分析或可视化定义并在当前授权下重新打开；面向授权用户的连接、查询及安全事件审计。明确数据保留、导出和删除规则。

**审核：** 验证结果行数/字节限制、精度与时区、失败/取消/部分结果；权限撤销和数据源解绑后不可越权重跑；审计不记录凭证、令牌或完整敏感结果。界面和导出能力须符合确认后的权限与保留策略。

## 阶段 11：Cloud

**交付：** 独立私有仓库内的组织、成员、邀请、角色、工作区和 Connector 管理；模型代理、用量、订阅和计费按已确认的商业方案实施。通过版本化公开接口使用共享核心，Community 不依赖 Cloud 私有实现。

## 阶段 12：发布与运维验收

**交付：** Community 可复现安装、配置、升级、健康检查、备份恢复、日志监控、许可清单和用户文档；Cloud 按独立发布路径完成运维方案。形成明确的版本兼容矩阵与已知限制。

**本机验收基准：** 复用用户本机已安装的 MySQL。以平台实际需要的连接、权限、迁移和事务行为能否通过验证为准。当前隔离验证使用 MySQL 26.7.0，MySQL 8.0 兼容性不作为本机验收的前置条件。验证继续使用独立测试库。需要实例级故障验证时，复用已安装的 MySQL 程序，在独立端口和数据目录运行测试实例。正式发布时，平台库与 Connector 接入的业务数据源分别记录已验证版本。

**审核：** 在干净环境按文档安装，验证备份恢复、带已有数据的升级、失败恢复、依赖许可与安全检查；分别测试承诺支持的 MySQL 版本及部署环境，完成关键场景的端到端回归。没有实际 MySQL 8.0 测试结果时，不将其列入已验证支持范围。
