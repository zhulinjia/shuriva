# AI Database Workspace

本目录是 Community 版的工程初始化，使用 pnpm + Turborepo 管理 TypeScript 工作区，并保留独立的 Go Connector。完整产品按现有设计逐步实现；Cloud 计划使用独立私有仓库。

## 当前状态

- `apps/community-web`：支持管理员、工作区、数据源与语义管理、AI 查询工作台；第七阶段增加本机会话、查询/分析/图表定义、结果表格和图表、执行历史及审计界面。
- `apps/community-api`：NestJS API 使用 Better Auth 管理本地账号和工作区；数据源与只读查询需显式启用。`GET /api/health` 仅说明进程可响应。
- `packages/ui`：共享的 Base UI 组件基础；尚未接入全部计划中的 shadcn/ui 和 AI Elements 模式。
- `connector/go`：独立 Go Connector，支持配对、结构扫描及受本机授权约束的只读查询；不开放数据库写入。
- `apps/community-api/migrations`：实际数据库结构和迁移来源；旧产品全量模型草稿保留在 `archive/schema-product-draft.prisma`，不是运行时迁移来源。
- `ui-prototype`：此前的独立静态界面原型，供参考；不作为正式前端运行时。

尚未实现工作区成员管理、Cloud 或 MCP。受控写入已完成 G3 实现与隔离联调，等待审核及 G4 准入，正式入口关闭。AI 模型调用和只读查询的支持范围及已知限制分别见 [第五阶段实施与审核记录](14-第五阶段实施与审核记录.md) 和 [第四阶段实施与审核记录](13-第四阶段实施与审核记录.md)。不要将当前工程直接用于生产。

第七阶段的启用、保留规则与审核证据见 [第七阶段实施与审核记录](16-第七阶段实施与审核记录.md)。保存内容不构成执行授权；重开定义不会自动执行，参数值必须重新填写。

第八阶段的 [受控写入设计](17-第八阶段受控写入设计与审核.md) 和 [核验、计时与恢复修订](20-第八阶段核验计时与恢复修订.md) 已获用户通过作为 G3 基线。当前 [G3 实现与审核记录](21-第八阶段G3实现与审核记录.md) 包含正式组件、AI 草稿、三操作安全执行器、显式迁移、签名协议和恢复；全部数据库验证仅使用另建的独立 13308 实例，原数据库与已有演示库均未连接。正式启动拒绝写入开关，等待 G4 及用户审核。

G1 [独立静态原型](18-第八阶段界面流程与原型说明.md) 继续保留作历史交互参考，不接 API 或数据库；正式工作台不导入该原型。G3 专用组件评审入口连接显式隔离服务，复用正式组件，不能把静态演示状态当作真实执行结果。

架构与代码组织重构、按目标并发协调及运行诊断见 [架构重构与诊断日志记录](22-架构重构与诊断日志实施记录.md)。平台请求编号可关联查询任务及 Connector 两端日志；诊断与持久业务审计分别管理，默认不记录 SQL、参数、结果和凭据。

G4 已开始按 [本机隔离验证记录](23-第八阶段G4本机隔离验证记录.md) 核验真实网络丢响应、Connector 崩溃、SQL 并发、认证与日志边界。W01–W64 的已覆盖和剩余项目逐项列出；用户已决定排除真实断电、实机休眠及物理磁盘故障验证，这三项不再阻断当前 G4，也不提供对应硬件行为保证。其余 G4 验证尚未全部通过，正式写入继续关闭。

## 本地开发

要求 Node.js 24（项目记录的开发版本为 `24.19.0`）、pnpm `12.14.0`，Connector 需要 Go 1.24 或更新版本。首次安装：

```bash
pnpm install
```

首次启动、管理员初始化和必要的环境配置请见 [Community API 开发说明](apps/community-api/README.md)。API 不会自动读取 .env；请先按说明设置数据库连接和密钥。浏览器访问 `http://127.0.0.1:5173/`。

常用检查：

```bash
pnpm typecheck
pnpm build
pnpm test
pnpm format:check
pnpm lint
pnpm check:boundaries
pnpm db:design-validate
```

数据库集成测试需要显式提供专用测试库连接。当前仅在 MySQL 26.7.0 上验证，MySQL 8.0 兼容性还需单独验证。旧版全量 Prisma 模型仅保留为设计参考，不应直接对开发库执行迁移。
