# Shuriva Data Security

## 1. 核心目标

确保 Shuriva 的数据库访问安全、
数据权限正确以及不同用户之间的数据隔离。

核心原则：

- 默认拒绝未经授权的访问。
- 默认只读。
- 数据库凭证不能暴露给浏览器。
- 前端隐藏字段不等于权限控制。
- AI 不拥有独立的数据访问权限。
- Mock 不能证明真实安全性。

## 2. Community 架构

Community：

- 用户自部署。
- 单用户、单工作区。
- Shuriva 后端直接连接数据库。
- 支持多个数据源连接。
- 不要求独立 Connector。
- 数据库凭证由自部署环境保护。
- 默认只读。

不得为了连接数据库增加不必要的独立网关服务。

## 3. Cloud 架构

Cloud：

- 多组织。
- 多成员。
- 多数据源。
- 成员权限。
- 字段权限。
- 行级权限。

Cloud 数据库连接方式尚未确定。

不得擅自决定 Cloud 必须：

- 使用 Connector
- 托管数据库凭证
- 使用浏览器直连
- 使用特定隧道服务

连接方案需要单独评估隐私、安全、网络和成本。

## 4. 多数据库

支持多种数据库引擎。

规划方向：

- PostgreSQL
- MySQL
- ClickHouse
- SQLite
- 其他按需求扩展

支持同一种数据库创建多个连接。

每个数据源独立管理：

- 连接配置
- 凭证
- 连接池
- Schema
- 状态
- 数据库能力

不能将不同数据库假设为完全相同。

## 5. 多数据源工作台

核心关系：

Workspace
-> DataSources
-> Queries
-> Components

要求：

- Query 明确绑定 DataSource。
- Component 明确绑定 Query。
- 查询执行必须指定数据源。
- 不同数据源独立执行。
- 不允许隐式跨库 JOIN。
- 数据关联必须明确配置或经过用户确认。
- 不同数据源的执行状态独立。

## 6. 用户权限

Cloud 需要支持：

### 用户权限

- 组织成员
- 用户角色
- 用户组
- 工作台访问
- 工作台编辑

### 数据源权限

- 数据源访问
- 表或数据集访问

### 字段权限

三种基本模式：

visible：原文可见
masked：脱敏可见
hidden：不可访问

### 行级权限

按业务需要支持：

- 全部授权记录
- 部门范围
- 门店范围
- 用户本人负责的记录

### 操作权限

独立控制：

- 查询
- 导出
- 创建工作台
- 编辑工作台
- 分享工作台
- 数据写操作

## 7. 权限执行

所有真实权限必须由可信服务端执行。

每次访问检查：

1. 用户身份
2. 组织身份
3. 工作台权限
4. 数据源权限
5. 数据集权限
6. 字段权限
7. 行级范围
8. 操作权限

禁止：

- 只在前端隐藏字段。
- 信任客户端传入的角色。
- 通过修改请求参数绕过行级权限。
- 将创建者权限自动传递给使用者。
- 先把敏感数据发送给 AI，再要求 AI 隐藏。

## 8. 字段权限

字段权限必须覆盖：

- 表格
- 详情
- 搜索
- 筛选
- 排序
- 导出
- AI 上下文
- 统计指标

脱敏必须在可信数据访问层完成。

不能将原始敏感数据发送到浏览器后再使用 CSS 或前端代码隐藏。

派生指标必须检查依赖字段。

## 9. SQL 安全

- 默认只读。
- 使用参数化查询。
- 限制可访问 Schema。
- 限制表和字段。
- 限制执行时间。
- 限制返回行数。
- 校验数据库能力。
- 对不同数据库实现必要适配。

不得仅使用字符串拼接或简单正则替换
实现 SQL 权限限制。

不得直接执行未经验证的 AI SQL。

## 10. 数据库凭证

禁止：

- 存入 localStorage。
- 暴露在浏览器代码。
- 输出到普通日志。
- 写入 AI Prompt。
- 通过前端接口返回完整凭证。

凭证需要在服务端安全保存和使用。

## 11. AI 数据访问

AI 生成查询计划不代表获得数据访问权限。

执行前必须检查：

- 当前用户
- 当前组织
- 当前数据源
- 当前字段权限
- 当前记录范围
- 当前操作权限

AI 不能绕过授权规则。

Cloud 还必须区分：
哪些数据可以在界面显示，
哪些数据允许进入 AI 上下文。

## 12. 缓存

缓存必须考虑：

- 用户身份
- 组织
- 数据源
- 查询条件
- 权限上下文
- 权限版本

权限变化后，旧缓存不得继续提供已失去授权的数据。

## 13. 安全审查触发条件

以下修改必须执行安全审查：

- 数据库连接
- SQL 执行
- 权限判断
- 字段过滤
- 行级过滤
- AI 查询
- 数据导出
- 缓存
- 数据写操作

## 14. 安全验收

必须验证：

- 未授权访问被拒绝。
- 字段权限不能被绕过。
- 行级权限不能被绕过。
- 导出遵守授权。
- AI 无法获取受限数据。
- 不同用户之间不存在数据串用。
- 不同数据源之间不存在上下文污染。

如果安全边界无法确认，应停止相关实现并说明风险。
