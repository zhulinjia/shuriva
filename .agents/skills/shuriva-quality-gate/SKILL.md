# Shuriva Quality Gate

## 1. 目标

确保每次重要开发完成后，
都有与修改范围相匹配的验证。

不能将：

- 代码写完
- 页面可以打开
- Mock 成功
- 单个测试通过

直接视为功能已经完整交付。

## 2. 技术基线

- React 19
- React Compiler
- TypeScript
- Vite 8
- Tailwind CSS 4
- pnpm
- Oxlint
- Playwright

具体版本以 package.json 和 pnpm-lock.yaml 为准。

## 3. 开发前检查

开始修改之前：

1. 检查 Git 状态。
2. 阅读 AGENTS.md。
3. 读取相关 Skills。
4. 检查项目结构。
5. 检查相关模块和调用方。
6. 检查现有测试。
7. 明确本次修改范围。

不得覆盖无关的用户修改。

## 4. 检查等级

### Level 1：小型修改

例如：

- 文案修改
- CSS 修改
- 简单布局调整

检查：

- Oxlint
- 相关页面检查

### Level 2：功能修改

例如：

- 新增组件
- 新增交互
- 修改状态管理
- 新增数据请求

检查：

- Oxlint
- TypeScript
- Vite Build
- 相关单元测试
- Playwright 回归测试

### Level 3：架构与安全修改

例如：

- 数据库连接
- 多数据源
- 用户权限
- SQL 执行
- AI 查询
- 缓存
- 身份认证

执行 Level 2 全部检查，并增加：

- 安全代码审查
- 越权测试
- 数据隔离测试
- 异常场景测试
- 真实数据库验证（适用时）

## 5. 标准检查命令

以 package.json 中实际存在的 scripts 为准：

pnpm lint

pnpm typecheck

pnpm build

pnpm test

pnpm exec playwright test

不存在的脚本不得假装执行。

需要先检查并补充对应配置。

## 6. 前端自动化测试

重要业务流程必须测试：

- 首页加载
- 工作台创建
- 工作台保存
- 工作台修改
- 放弃修改
- 多数据源绑定
- 数据源切换
- 搜索
- 筛选
- 排序
- 分页
- 详情查看
- 数据源离线
- 查询失败
- 空数据状态
- 刷新恢复

## 7. 权限测试

涉及权限修改时必须验证：

- 不同用户实际获得的数据。
- 字段权限是否有效。
- 脱敏是否发生在可信边界。
- 行级限制是否有效。
- 导出是否遵守权限。
- AI 是否能够绕过限制。
- 缓存是否发生权限串用。

仅检查 UI 是否隐藏字段不算通过。

## 8. 代码审查

修改完成后检查：

- 是否存在重复代码。
- 是否引入不必要的抽象。
- 是否影响其他模块。
- 是否破坏接口契约。
- 是否存在错误处理缺失。
- 是否引入安全问题。
- 是否存在未使用依赖。
- 是否存在无效交互。

## 9. 回归验证

完成检查后：

1. 修复发现的问题。
2. 再次执行相关检查。
3. 检查 Git Diff。
4. 确认修改范围。
5. 确认未破坏已有功能。

## 10. 交付报告

重要任务完成后，输出：

### 本次修改

说明完成内容。

### 修改文件

列出新增、修改和删除的文件。

### 验证结果

分别说明：

- Oxlint
- TypeScript
- Build
- Unit Tests
- Playwright
- 安全验证（适用时）

### 未完成事项

列出：

- 未执行的测试
- 失败的检查
- 当前环境限制
- 尚未实现的能力

### 风险说明

说明是否影响：

- 数据安全
- 用户权限
- 数据库连接
- 多数据源
- 现有业务模块

## 11. 禁止事项

- 不得伪造测试通过结果。
- 不得删除失败测试来获得通过。
- 不得隐瞒构建失败。
- 不得将 Mock 成功描述为真实能力。
- 不得将前端隐藏描述为权限验证。
- 不得未经确认升级主要依赖。
- 不得将未验证事项描述为已完成。
